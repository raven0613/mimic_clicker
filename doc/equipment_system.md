# 裝備卡與局內裝備系統規格

本文件承接 [spec.md](./spec.md) 的裝備規則，定義裝備的附著、掉落、收集、裝備欄、背包管理、局內換裝與戰鬥效果。主武器持有與開局快照見[主武器商店規格](./weapon_shop.md)，局外「裝備槽 III」與未來第 4 槽的成長方式見[永久升級規格](./permanent_upgrades.md)，效果卡共用的外掛卡規則見[效果卡規格](./effect_cards.md)，實作分層見[前端與遊戲執行架構](./technical_architecture.md)。

## 1. 系統定位與本次範圍

- 裝備是只在目前單局存在的即時強化；不寫入存檔，也不跨局保留。
- 本次完成外部可見裝備、內部隱藏裝備、局內裝備欄、可開啟的背包管理、`sword`、`ring` 兩件裝備，以及回合結束自動出售的完整端到端流程。
- 裝備鬆動／震落、手動選擇出售、素材轉換與裝備跨局保存不在本次範圍；槽位只依局外永久等級在開局時解析，不提供局內購買或擴充操作。
- 回合收尾時先凍結成功取得裝備的出售快照並計算收益，再清除裝備欄、背包內容、飛行中裝備、槽位保留、Ring 計數與待結算追加攻擊；局內裝備本體仍不跨局保留。

## 2. 裝備定義與素材

每個裝備 definition 至少包含唯一 id、稀有度、外掛卡素材、效果種類與效果參數。素材資料夾只用於內容整理，不限制可裝槽位：

| 裝備 id | 稀有度 | 素材 | 規則 |
| --- | --- | --- | --- |
| `sword` | `N` | `src/assets/equipment/weapon/sword.png` | 每件提供可疊加的固定武器傷害加成 |
| `ring` | `SR` | `src/assets/equipment/decoration/ring_pearl.png` | 累積有效手動武器命中後，依已裝備 Ring 數量排入追加攻擊 |

- 每張可見或掉落中的裝備卡都必須由既有 `effects/card_frame/normal.png` 卡框與對應裝備素材疊成同一個卡面 Container；裝備素材不得脫離卡框單獨顯示。卡框與裝備素材使用相同 anchor、顯示尺寸與 nearest-neighbor 取樣。
- 同一攜帶者的外掛卡不得出現重複的完整內容識別 `kind:id`；同 id 裝備可以由不同攜帶者掉落，並可同時裝進不同槽位。
- `N` Sword 不建立任何光暈。`SR` Ring 只依共用稀有度取得紫色卡框形光暈，與同為 `SR` 的效果卡共用清晰描邊、模糊層、顏色與呼吸設定；不得依裝備 id 選擇光暈或保留內容專屬光暈資源。基準圓角矩形必須使用與卡框相同的寬高與輪廓，不得先放大或向外 offset 幾何；只有 blur 產生的柔光像素可以自然延伸到卡框外。
- Ring 的 `SR` 光暈在附著於怪物、掉落飛行與裝備完成三種狀態都必須保留，並跟隨卡片 transform。

## 3. 外掛卡共用容量與抽選

- 效果卡與外部可見裝備組成同一個外掛卡候選池，共用攜帶者的單一容量與右上角扇形排列，不建立裝備專用的第二套附著系統。
- 普通寶箱與 Jackpot 偽裝外殼沿用目前外皮的候選機率與容量。各內容先依自身 config 進入候選集合；候選超量時，以可注入亂數公平、無重複地裁切到容量上限，不得讓效果卡或裝備因程式宣告順序固定優先。
- Jackpot 真身不套用普通候選機率；它依 `attachedCardConfig.capacity.jackpot` 決定目標張數，再從當下可用的效果卡與裝備共同內容池公平、無重複抽選。唯一內容不足時全部附上，不以重複卡補滿。
- Jackpot 偽裝外殼的內容在破殼時完成自己的結算，不轉移到真身；真身以相同共用選卡模組建立新的獨立內容。
- 外掛容量、候選率、Jackpot 張數分布與扇形幾何都以 config 為準；規格不保存測試中的實際數值。

## 4. 內部隱藏裝備

- 每次建立可戰鬥的普通寶箱、Jackpot 偽裝外殼或 Jackpot 真身時，各自執行一次隱藏裝備產生流程。
- 隱藏流程先依 config 的 `none` 與各裝備稀有度機率選出結果；若結果不是 `none`，再從該稀有度目前可用的裝備池公平選取一件。因此單一攜帶者的內部隱藏裝備最多一件。
- 隱藏裝備不占用外掛卡容量、不顯示在攜帶者身上，也不受外部可見裝備的掉落率影響。
- 選取隱藏裝備時排除同一攜帶者已顯示的裝備 id，避免同一件裝備同時以可見與隱藏來源出現在同一攜帶者。
- 隱藏稀有度分布與各稀有度可用池由 config 管理，並使用可注入亂數；相同 seed 與內容狀態必須產生相同結果。

## 5. 擊破與掉落結算

普通寶箱或 Jackpot 真身死亡，以及 Jackpot 偽裝外殼被打破時，裝備流程固定為：

1. 先凍結該攜帶者尚未結算的可見裝備與內部隱藏裝備，避免換圖或銷毀 Container 後遺失資料。
2. 每張可見裝備各自依 `visibleAttachmentDropChance` 做一次掉落判定；成功者進入獎勵批次，失敗者只播放可辨識的散失／淡出，不保留槽位也不取得。
3. 內部隱藏裝備若存在，直接加入同一獎勵批次，不再套用可見裝備掉落率。
4. 對成功掉落批次原子分配目的地並保留裝備槽，再開始各張裝備的噴出與收集動畫。

- 同一來源的每件裝備只結算一次；效果卡觸發、裝備掉落與金錢噴散可由同一死亡事件並行開始。
- Jackpot 偽裝外殼被打破也執行完整裝備結算與效果卡觸發，但維持不產生金錢；外殼內容不轉移到真身。
- Jackpot 真身擁有自己新生成的可見與隱藏裝備；真身死亡時獨立結算，並正常產生 Jackpot 金錢。
- 外部可見掉落機率是裝備 config 的可調值，不依攻擊次數、傷害來源或已延後的鬆動值修正。
- 目前永久升級不修改可見裝備掉落率、隱藏裝備機率或稀有度，也不提供裝備回收率升級。

## 6. 裝備欄、背包與目的地保留

- 每局開始時以 `initialSlotCount + additionalSlotCountByLevel[永久裝備槽等級]` 解析本局通用裝備槽數；目前等級 `0` 為基礎 2 格，購買「裝備槽 III」後的等級 `1` 為 3 格。解析結果在該局固定，不因局外狀態後續改變而中途增減。
- `additionalSlotCountByLevel` 由永久升級 config 管理；未來第 4 槽只在同一等級表追加等級 `2`，不得新增另一個槽位布林值或平行分配系統。
- 畫面下方依解析後數量顯示通用裝備槽；槽位不限制 weapon、decoration、稀有度或裝備 id。
- 成功掉落批次建立時，先讀取尚未占用或保留的空槽。若同批裝備超過空槽數，先按稀有度由高至低排序，同稀有度維持批次中的穩定順序，再逐一保留槽位。
- 槽位保留必須是核心狀態的原子操作；飛行中的保留槽視為已占用，後續同時掉落不得再把另一件裝備指向同一格。
- 沒有取得槽位的裝備飛向 `src/assets/equipment/backpack.png`。背包容量不設上限；抵達背包後成為可管理但不提供能力的局內卡片。
- 抵達已保留槽位的同一刻，該裝備才從 `reserved` 轉為 `equipped`、固定顯示在該槽並啟用能力；噴出、等待或飛行途中都不生效。
- 抵達背包的裝備記錄為 `stored`，不提供任何能力。自動收集不替換現有裝備；只有玩家在背包面板發出的換裝操作能改變既有槽位。
- 同一 id 可占用多個槽位；Sword 效果線性疊加，Ring 效果依第 8 節處理。

### 6.1 局內卡片實例

- 每件成功取得的裝備都是獨立實例，至少保存穩定的 `instanceId`、`equipmentId`、稀有度、`acquiredSequence` 與目前位置；同 id 重複裝備不得合併成一筆核心狀態。
- `acquiredSequence` 在成功掉落批次成立時依局內單調序列分配，不使用牆鐘。裝備被卸下或換位時保留原序列，不會因回到背包而變成最新取得。
- 裝備位置只能經過明確狀態轉移落在飛行／保留、`equipped`、`stored` 或取消狀態；排序只是 `stored` 清單的衍生視圖，不得重排核心取得紀錄。
- 飛往某槽的裝備仍未進入背包清單；該 `reserved` 槽在面板與裝備欄中顯示「即將抵達」並禁止放置、移動或交換。關閉背包並恢復遊戲後，原收集動畫繼續前往同一目的地。

### 6.2 背包面板、排序與資訊層級

- 點擊 HUD 背包 icon 在畫面中央開啟 React／SCSS 面板；面板只列出當下位置為 `stored` 的裝備。已裝備與飛行中的裝備不重複出現在清單。
- 面板最大高度必須保留畫面下方裝備欄與向下拖曳路徑；卡片超出可用高度時只讓清單區內部捲動，標題、排序控制與關閉操作保持可見。
- 重複裝備逐張顯示。每張卡在常態只顯示卡圖與名稱，稀有度沿用既有卡框／光暈色彩，不額外常駐稀有度文字；無障礙名稱仍須包含裝備名稱與稀有度，避免只以顏色傳達給輔助工具。
- 背包卡與裝備欄卡共用同一套 hover／鍵盤 focus tooltip，顯示該裝備目前 definition 對應的效果文字。效果文字由裝備 definition 與正式 config 產生的顯示資料提供，React 不另寫傷害或觸發數字；拖曳期間隱藏 tooltip。
- tooltip 必須留在 viewport 安全範圍內，不遮住目前拖曳目標；鍵盤 focus 也可取得同一資訊。
- 玩家可在「取得時間」與「稀有度」間切換排序，預設為取得時間。取得時間排序依 `acquiredSequence` 由新到舊；稀有度排序固定為 `UR → SSR → SR → R → N`，同稀有度再依取得順序由新到舊。
- 排序模式是瀏覽器內 UI 偏好，使用 `localStorage` 保存最新設定；它不屬於正式進度，不納入 IndexedDB、進度匯出／匯入或 Reset。讀取失敗時回退到取得時間排序，不影響單局。
- 背包外的戰場區域只使用不帶濾鏡的半透明遮罩表達輸入已鎖定；不得使用 `filter`、`backdrop-filter`、高斯模糊或會降低裝備辨識度的全畫面效果。完整裝備欄、槽內實際卡圖、合法目的地回饋與拖曳預覽都位於遮罩上方，保持原有清晰度、色彩與對比。

### 6.3 拖曳、點選替代操作與換裝

- 背包卡可拖到空槽直接裝備，也可拖到已占用槽替換；被替換卡保留原 `acquiredSequence` 回到背包，再依目前排序插入正確位置。
- 已裝備卡可拖回背包；裝備槽之間也可互換，拖到空槽時則移動到該槽。所有操作都以 `instanceId` 為目標，由裝備核心一次提交完整結果，React 不自行改效果或先後次序。
- 拖曳時顯示清楚的卡片預覽與合法目的地回饋；`reserved` 或其他非法目的地維持鎖定。放到非法區域、按 Escape 或中斷拖曳時回到原位，不產生部分換裝。
- 背包卡框與卡圖必須停用瀏覽器原生 HTML image drag；自訂 pointer 拖曳在按下後掌握該 pointer，移動與放開不因游標離開來源卡而遺失。只有正常 `pointerup` 落在合法目的地時提交，`pointercancel`、Escape、失去追蹤或原生 drag 中斷都只取消，不得誤提交。
- 除拖曳外，必須提供「先選卡、再選目的地」的完整替代路徑；選擇已裝備卡後可選背包區或另一槽，選擇背包卡後可選合法槽位。成功操作後面板保持開啟，方便連續整理。
- 面板可由背包 icon 再次切換、明確關閉按鈕、點擊面板外背景或 Escape 關閉；關閉前先取消尚未提交的拖曳／點選狀態。
- 換裝提交成功的同一核心步驟立即重算已裝備效果。Sword 只影響之後的攻擊；已排入佇列的 Ring 追加攻擊依原快照完整播放。卸下最後一枚 Ring 時清除尚未達觸發門檻的有效命中計數，仍留有至少一枚時保留計數；新裝上的 Ring 只參與之後新建立的批次。

### 6.4 開啟背包時的暫停

- `backpackConfig.pauseGameWhileOpen` 初始為 `true`。開啟面板時凍結主倒數、Jackpot 倒數、生成、位移、傷害、自動攻擊、Ring 佇列、掉落收集與所有遊戲場景動畫；不得在恢復時補算暫停期間的 `deltaMS`。
- 暫停只凍結遊戲更新，Pixi renderer 持續繪製，React 背包面板與其短促 UI 動畫仍可操作；換裝結果因此能在暫停畫面立即更新。React HUD 中代表遊戲進度的 SCSS 動畫也必須凍結。
- 背包暫停不等於結算視覺。背包流程不得套用結算使用的高斯模糊；半透明戰場遮罩只負責區分不可操作背景，不得覆蓋或調暗裝備欄、槽內卡圖、拖曳預覽與 tooltip。
- 背包開啟是 `playing` 內與 Jackpot 階段正交的 UI 狀態；開啟或關閉不得重設 Jackpot 偽裝、追逐、僵直或逃跑階段。本局進入收尾時強制關閉面板並取消未提交操作。
- 若 config 設為 `false`，遊戲更新與倒數照常推進，但面板仍攔截背景戰鬥輸入；新抵達背包的裝備依最新核心快照加入清單。若本局在面板開啟時結束，先取消操作並關閉面板，再進入既有收尾流程。

## 7. 掉落與收集動畫

- 同一擊破／破殼事件成立時，裝備與金幣同時向外噴出；裝備的收集排程必須讓它比同事件的金幣更晚抵達 HUD，形成可辨識的節奏差。
- 成功的可見裝備與存在的隱藏裝備必須以具有明顯高度的拋物線向外灑出，使用可注入初速、角度、重力與局部落地高度的逐幀運動；不得以固定短距離線性位移代替噴出。
- 裝備落地後依 config 反彈指定次數並逐次衰減水平與垂直速度，再進入停留狀態。裝備卡面與其稀有度光暈在拋射、旋轉、反彈與停留期間必須共用同一 transform。
- 裝備與金幣共用同一個純資料 burst／bounce 運動核心，但各自保有獨立 config；不得複製一套只改名稱的裝備物理。裝備拋射高度、速度、重力、落地範圍、反彈次數與速度保留率都由 config 管理。
- 裝備只有在完成拋射／反彈，且同事件金幣已完成收集與額外錯開時間後，才能由停留位置飛向已保留槽位或背包。若金幣較早完成，仍須等待裝備落地；若裝備較早落地，則在原地等待金幣事件。
- 沒有金幣流程的 Jackpot 偽裝外殼，使用 config 的 fallback 等待時間後開始收集。
- 裝備噴出、停留、飛行、錯開與 fallback 時間都使用 Pixi ticker 的 `deltaMS` 累積，不使用 `setTimeout`、`Date.now()` 或真實牆鐘。
- React HUD 只提供裝備槽與背包 icon 的 viewport 目標矩形；Pixi runtime 換算成 canvas 座標並執行逐幀動畫。React 不決定槽位分配或裝備何時生效。
- 目標位置在動畫期間改變時，runtime 使用最新合法座標平滑重定向；目標暫時不可用時保留邏輯目的地，但不得誤啟用裝備。
- 回合收尾會取消尚未抵達的收集動畫及其槽位保留；取消後不啟用也不進背包，但只要該裝備在倒數結束前已完成成功掉落判定，就必須由收尾前的出售快照計入結算。

## 8. 裝備效果

### 8.1 Sword

- 每件已裝備 Sword 將 `weaponDamageBonus` 加到本局主武器快照的基礎攻擊力；多件以加法疊加。手動攻擊與懸停自動攻擊使用同一公式並取得相同加成。
- 加成只計入裝備完成後的新攻擊，不追溯先前攻擊，也不改寫效果卡以初始武器 definition 推導的既有公式。
- 加成數值只存在裝備 config，測試必須匯入同一設定。

### 8.2 Ring 的有效命中計數

- 至少一枚 Ring 已裝備後，使用玩家全域、跨目標的單一計數器累積「有效手動武器命中」。
- 只有通過每目標武器傷害間隔、確實對可受擊實體造成傷害的手動點擊才增加計數。間隔內被拒絕的點擊、效果卡傷害、Ring 追加攻擊與未造成傷害的輸入都不計數。
- 計數達到 `acceptedManualHitsPerTrigger` 時歸零，並以觸發該次命中的最終武器傷害、目標 runtime identity、該次實際游標點擊位置與已裝備 Ring 數量建立一批追加攻擊快照；這個游標位置是整批 Ring 視覺的固定原點，之後移動游標、目標移動或目標失效都不改寫，之後才抵達的 Ring 也不加入既有批次。
- 計數器由已裝備的 Ring 共用，不因裝備多枚而讓一次手動命中重複增加計數。

### 8.3 Ring 追加攻擊

- 每枚快照中的 Ring 產生一段追加攻擊；目標在該段結算時仍可受擊，才造成 `triggeringWeaponDamage × additionalDamageMultiplier` 傷害。第一段也必須與觸發命中分開，所有段數再以固定 `additionalHitIntervalMs` 依序結算，不得與觸發命中同時出現。
- 所有 Ring 批次共用玩家的一條序列佇列；前一批尚未結束時，新批次附加在佇列尾端，任兩段相鄰追加攻擊都維持相同固定間隔，不合併成同時傷害。
- 每段到達結算時點都必須以批次快照的游標點擊位置為原點，加上 `additionalHitEffectOffset` 建立向右上的 `effects/hit.png` 視覺；初始偏移為 `(28, -22)`。目標仍可受擊時，該段傷害與視覺在同一 ticker 時點發生。偏移只改變視覺位置，不改變命中座標或範圍。
- Ring 追加 hit 沿用手動與懸停自動攻擊共用的 frame texture 與動畫播放器，但建立顯示物件時套用 Ring 專用 tint，使追加段能立刻與置中的普通命中及左下自動命中區分。顏色在 config 以容易調整的 CSS `#RRGGBB` 字串保存，初始為 `#ff825c`；Pixi 邊界只在建立該次效果時轉成 tint number，不得在 ticker 每幀轉換，也不得為此增加 filter、mask 或重複 Sprite pass。
- 目標仍可受擊時，追加攻擊繞過每目標武器傷害間隔，但沿用唯一的傷害、裂紋、死亡、收益、效果卡與 Jackpot 結算入口；它不是手動武器命中，不增加 Ring 計數，也不能遞迴觸發新的 Ring 批次。
- 批次鎖定觸發命中的同一 runtime 實體，不得把追加攻擊轉移給其他目標。本局仍在進行時，目標死亡、離場或變成不可受擊狀態都不得取消已排入佇列的剩餘段數；每段仍按原固定間隔在批次保存的游標原點右上播放 Ring hit 視覺，但不再造成傷害、裂紋、死亡、收益、效果卡或裝備結算。目標是否仍存在只影響傷害資格，不得把視覺改回目標中心或目前游標位置。
- 打破 Jackpot 偽裝外殼時 runtime 實體保持相同；該次命中建立的待結算 Ring 追加攻擊可在固定間隔後命中已揭露的 Jackpot 真身。
- 主倒數耗盡或回合收尾時取消所有未結算段數，不得在戰鬥結束後造成傷害或收益。

## 9. 結算自動出售

### 9.1 出售快照

- 主倒數結束時立即禁止新的傷害、掉落與收益，並對當下已成功取得的裝備建立一次不可變出售快照；若 Jackpot 尚須完成既有退場，退場只延後結算 UI，不得改變已凍結的出售內容。
- 出售範圍包含已裝備的 `equipped`、已進背包的 `stored`，以及倒數結束前已成功掉落但仍處於 `airborne`、`resting` 或 `collecting` 的裝備。
- 可見裝備掉落判定失敗、仍附著在未擊破目標上，或從未進入成功獎勵批次的裝備不屬於玩家取得物，不得出售。
- 同一裝備 reward instance 只能進入快照一次；建立快照後才取消動畫、釋放槽位保留並清除局內裝備，避免飛行中裝備漏算或同時出現在兩種狀態而重複出售。

### 9.2 價格規則

初版出售只產生金幣。價格由穩定的稀有度基準決定，不以該局戰鬥收益百分比動態回推：

```text
單件售價 = round(basePriceGold × rarityPriceMultiplier)
同 id 小計 = 單件售價 × 數量
裝備出售收益 = 所有同 id 小計總和
本局總收益 = 戰鬥收益 + 裝備出售收益
```

`settlementConfig.equipmentSale` 的初始值固定為：

| 欄位 | 初始值 |
| --- | ---: |
| `basePriceGold` | 6 |
| `rarityPriceMultipliers.N` | 1 |
| `rarityPriceMultipliers.R` | 2 |
| `rarityPriceMultipliers.SR` | 4.5 |
| `rarityPriceMultipliers.SSR` | 8 |
| `rarityPriceMultipliers.UR` | 16 |

因此初版 `N` Sword 單件內部計價為 `6`，`SR` Ring 為 `27`。SR 倍率由固定 seed 全矩陣校準，避免全解鎖階段因高血量寶箱降低掉落件數而跌破出售收益占比門檻。這些單價只供核心計算與測試使用，不在結算 UI 顯示。未來委託可以用明確規則替代符合條件項目的普通出售小計，但不改寫普通稀有度價格。

### 9.3 結算顯示

- 重複裝備依精確 equipment id 合併，不因稀有度相同而合併不同裝備。
- 每列只顯示「裝備名稱 × 數量」及乘算後小計，例如 `Sword × 5  +30`；不得顯示單價。
- 先顯示戰鬥收益，再以每組 `100 ms` 的初始間隔快速揭示出售列，出售列階段最多 `400 ms`；分組過多時，實際間隔取「初始間隔」與「階段上限 ÷ 分組數」的較小值，確保全部列都能顯示。最後以 `300 ms` 數字滾動合併到本局總收益，整段最多 `700 ms`。數值由 `animationConfig.settlementEquipmentSale` 管理。
- 玩家在揭示期間點擊或確認時立即快轉至完整結果；快轉只完成顯示，不得再次計算或入帳。揭示完成後才允許繼續至解鎖提示或下一個流程。
- 本局沒有可出售裝備時完全略過出售區塊與等待，直接顯示戰鬥收益作為本局總收益。

## 10. config 權責

執行中的裝備數值以 `src/configs/equipmentConfig.ts`、`src/configs/attachedCardConfig.ts`、`src/configs/combatConfig.ts`、`src/configs/animationConfig.ts`、`src/configs/backpackConfig.ts` 與永久升級 config 為唯一真相。規格只固定欄位語意、公式、合法範圍與時序，不記錄測試用數值；當前平衡報告直接讀取正式 config，新報告取代舊報告，不保留過時快照。

| config 欄位 | 責任與限制 |
| --- | --- |
| `initialSlotCount` | 未購買任何永久槽位里程碑時的基礎通用裝備槽數；必須為非負整數 |
| `permanentUpgradeConfig.equipmentSlots.additionalSlotCountByLevel` | 永久裝備槽等級對應的額外槽數；目前依序為 0、1，未來第 4 槽在同一表追加 2 |
| `visibleAttachmentDropChance` | 每張外部可見裝備的獨立成功率；限制在有效機率範圍 |
| `hiddenDropRarityChances` | `none` 與各裝備稀有度的完整機率分布 |
| `weaponDamageBonus` | 每件 Sword 提供的固定武器傷害加成 |
| `acceptedManualHitsPerTrigger` | Ring 觸發所需的有效手動命中數；必須為正整數 |
| `additionalDamageMultiplier` | Ring 每段追加攻擊相對觸發武器傷害的倍率；必須大於零 |
| `additionalHitIntervalMs` | 觸發命中後至第一段及後續各段之間共用的固定間隔；必須大於零 |
| `additionalHitEffectOffset` | Ring 追加 hit 特效相對觸發該批次之實際游標點擊位置的右上偏移；初始為 `(28, -22)` |
| `additionalHitEffectTintColor` | Ring 追加 hit 的 CSS `#RRGGBB` tint 字串；由 Pixi 顯示邊界在建立效果時轉換，不保存 `0x...` 數值 |
| `backpackConfig.pauseGameWhileOpen` | 開啟背包時是否凍結完整遊戲更新；初始為 `true`，只控制暫停，不決定面板可否開啟 |
| `settlementConfig.equipmentSale` | 自動出售的金幣基價與 `N／R／SR／SSR／UR` 稀有度倍率；不得依本局即時收益動態改價 |
| 裝備收集動畫欄位 | 拋射角度／速度、重力、落地範圍、反彈次數／保留率、停留、比金幣晚抵達的錯開、飛行速度／時間及無金幣 fallback |
| `animationConfig.settlementEquipmentSale` | 分組列揭示間隔、揭示階段上限與總收益數字滾動時間；只控制顯示，不控制入帳 |
| 稀有度光暈欄位 | 由共用外掛卡 config 管理 `R`／`SR`／`SSR`／`UR` 的卡形輪廓、色彩、線寬、模糊／padding、透明度與呼吸；裝備不得另設依 id 命名的光暈欄位 |

## 11. 驗證要求

### 11.1 確定性核心測試

- 固定 seed 下，共用外掛候選、公平容量裁切、Jackpot 保證選卡與隱藏稀有度抽選可重複；隱藏裝備最多一件且不與同攜帶者可見裝備重複。
- 可見裝備掉落機率的失敗、成功與邊界結果由注入亂數控制；失敗不得保留槽位或取得裝備。
- 同一批多件掉落會原子保留不同空槽；容量不足時依規則分配，剩餘裝備進入背包，已保留槽不會被另一批重複占用或被玩家換裝覆蓋。
- 永久裝備槽等級 `0` 與 `1` 分別建立 2 格與 3 格，分配、保留、HUD 目標與回合清理都使用同一解析結果；模擬追加等級 `2` 時同一路徑可建立 4 格。
- 裝備在飛行中不生效，抵達槽位後才生效；抵達背包不生效，回合清理會取消飛行、保留與待結算攻擊。
- Sword 重複裝備依 config 線性疊加。
- Ring 只計算有效手動武器命中；跨目標共用計數，多枚 Ring 依 config 固定間隔順序結算，傷害使用觸發命中的快照，且不遞迴。
- Ring 批次保存觸發命中的實際游標點擊位置，所有段數都以該原點加上正式右上偏移建立視覺；之後游標或目標移動不改寫。目標死亡、離場或不可受擊後，剩餘段數仍依序產生視覺但不造成任何遊戲結果；打破 Jackpot 偽裝外殼時可沿同一 runtime 身分命中真身；主倒數耗盡或回合收尾時才取消所有未結算段數。
- 裝備實例 identity 與取得序列在換裝後保持穩定；兩種排序皆可重複，切換排序不改核心狀態，重複 id 仍可逐張操作。
- 背包與空槽、占用槽、裝備欄及非法／保留目的地的各種移動都以單一原子結果完成；替換後能力立即以最新裝備計算，Ring 計數與既有佇列符合第 6.3 節。
- `pauseGameWhileOpen` 啟用時，指定 `deltaMS` 不會推進倒數、戰鬥、移動、Ring 或收集動畫，關閉後從原進度繼續且不補算；停用時則只阻擋背景輸入。
- Jackpot 外殼破裂會結算可見與隱藏裝備但不產生金錢；外殼與真身內容各自只結算一次。
- 出售快照同時涵蓋 equipped、stored 與已成功掉落的飛行中裝備，排除掉落失敗及仍附著裝備；同一 reward instance 不會重複計入。
- 單件售價、同 id 數量與小計、出售總額及本局總收益都直接讀取正式 config；改變戰鬥收益不得改變同一裝備的單件售價。
- 沒有裝備、只有一件、同 id 多件及不同 id／相同稀有度等案例都能得到確定且正確的分組結果。
- 所有測試從正式 config 讀取數值，時間以參數或 `deltaMS` 注入，不依賴真實時間與隨機結果。

### 11.2 平衡與人工檢查

- Sword、Ring、裝備附著／掉落與隱藏稀有度都會改變擊殺、收益或 Jackpot 捕獲機會，完成實作前必須依[初版核心平衡驗證閘門](./progression_and_validation.md#182-初版核心平衡驗證閘門)執行受影響的核心測試與固定 seed 模擬；Sword 與 Ring 的代表案例須交叉三種正式主武器，不能只驗證初始武器。
- 人工確認每張裝備素材都疊在既有 normal card frame 內，附著、拋射、反彈、收集與槽位顯示期間都不會脫框。
- 人工確認裝備與效果卡共享一個可讀扇形；`N` Sword 無光暈，Ring 的 `SR` 紫色清晰外框及模糊層在附著、飛行與槽位中都與 card frame 外緣完全貼合，且與其他 `SR` 卡外觀一致。柔光不得形成較大的第二層外框、變成圓形、遮住鄰卡、被 bounds 裁切或因每幀重畫而閃爍。
- 人工確認裝備以足夠高度的拋物線灑出並清楚落地反彈，同事件的裝備仍比金幣稍晚抵達；多件裝備可同時飛往不同槽，滿槽後則飛向背包 icon。
- 人工確認裝備抵達槽位的瞬間與傷害變化一致，飛行中及背包內不會提前生效。
- 人工確認中央背包在常見 viewport 不遮住必要關閉操作；卡片常態只顯示卡圖與名稱，稀有度色彩清楚，背包與裝備欄 hover／focus 都能顯示相同效果 tooltip。
- 人工確認背包開啟時只有不帶濾鏡的半透明戰場遮罩，完整裝備欄、槽內卡圖、拖曳預覽與 tooltip 保持清晰且位於遮罩上方；不得沿用結算高斯模糊或把裝備一起調暗。
- 人工確認從卡框、卡圖、名稱任一位置開始拖曳，以及先選卡再選目的地兩條路徑，都能完成裝備、替換、卸下與槽位互換；瀏覽器原生圖片拖曳不會搶走 pointer，保留槽清楚鎖定，`pointercancel` 與其他取消操作可安全回原位且不提交，成功後面板維持開啟並依目前模式排序。
- 背包換裝會影響攻擊與收益；完成實作前，固定 seed 平衡模擬除無換裝基準外，還必須以 balance simulation config 定義具名、可重複的代表性換裝策略並重新通過核心平衡閘門，不得把 UI 操作時間或牆鐘帶入模擬。
- 人工確認 Ring 每段追加 hit 都從觸發批次的手動點擊位置快照往右上錯開，且 config tint 能明顯區分置中手動 hit、左下自動 hit 與右上追加 hit，不會讀成同一幀或同一位置的重疊傷害；觸發後移動游標／目標不得讓該批視覺跳位，觸發命中或前段追加攻擊擊殺目標後所有剩餘動畫仍須完整播放，回合收尾後則不得續播。
- 固定 seed 模擬必須輸出裝備出售收益及其占本局最終總收益比例；目標區間由 `balanceSimulationConfig` 管理，詳見[初版核心平衡驗證閘門](./progression_and_validation.md#182-初版核心平衡驗證閘門)。
- 人工確認重複裝備只顯示合併後小計、不顯示單價；逐列揭示、總收益滾動、點擊快轉與零裝備略過皆俐落，且任何顯示中斷都不改變已保存收益。
