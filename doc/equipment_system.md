# 裝備卡與局內裝備系統規格

本文件承接 [spec.md](./spec.md) 的裝備規則，定義裝備的附著、掉落、收集、裝備欄、背包暫存與戰鬥效果。效果卡共用的外掛卡規則見[效果卡規格](./effect_cards.md)，實作分層見[前端與遊戲執行架構](./technical_architecture.md)。

## 1. 系統定位與本次範圍

- 裝備是只在目前單局存在的即時強化；不寫入存檔，也不跨局保留。
- 本次完成外部可見裝備、內部隱藏裝備、局內裝備欄、未啟用背包入口，以及 `sword`、`ring` 兩件裝備的完整端到端流程。
- 裝備鬆動／震落、背包管理、換裝、出售、素材轉換、槽位擴充與跨局保存不在本次範圍。
- 回合收尾時清除裝備欄、背包暫存、飛行中裝備、槽位保留、Ring 計數與待結算追加攻擊；本次不產生裝備出售收益。

## 2. 裝備定義與素材

每個裝備 definition 至少包含唯一 id、稀有度、外掛卡素材、效果種類與效果參數。素材資料夾只用於內容整理，不限制可裝槽位：

| 裝備 id | 稀有度 | 素材 | 規則 |
| --- | --- | --- | --- |
| `sword` | `N` | `src/assets/equipment/weapon/sword.png` | 每件提供可疊加的固定武器傷害加成 |
| `ring` | `SR` | `src/assets/equipment/decoration/ring_pearl.png` | 累積有效手動武器命中後，依已裝備 Ring 數量排入追加攻擊 |

- 每張可見或掉落中的裝備卡都必須由既有 `effects/card_frame/normal.png` 卡框與對應裝備素材疊成同一個卡面 Container；裝備素材不得脫離卡框單獨顯示。卡框與裝備素材使用相同 anchor、顯示尺寸與 nearest-neighbor 取樣。
- 同一攜帶者的外掛卡不得出現重複的完整內容識別 `kind:id`；同 id 裝備可以由不同攜帶者掉落，並可同時裝進不同槽位。
- `N` Sword 不建立任何光暈。`SR` Ring 只依共用稀有度取得紫色卡框形光暈，與同為 `SR` 的效果卡共用清晰描邊、模糊層、顏色與呼吸設定；不得依裝備 id 選擇光暈或保留內容專屬光暈資源。基準圓角矩形必須使用與卡框相同的寬高與輪廓，不得先放大或向外 offset 幾何；只有 blur 產生的柔光像素可以自然延伸到卡框外。
- Ring 的 `SR` 光暈在附著於怪物、掉落飛行與裝備完成三種狀態都必須保留，並跟隨卡片 transform。

## 3. 外掛卡共用容量與抽選

- 效果卡與外部可見裝備組成同一個外掛卡候選池，共用攜帶者的單一容量與右上角扇形排列，不建立裝備專用的第二套附著系統。
- 普通寶箱與 Jackpot 偽裝外殼沿用目前外皮的候選機率與容量。各內容先依自身 config 進入候選集合；候選超量時，以可注入亂數公平、無重複地裁切到容量上限，不得讓效果卡或裝備因程式宣告順序固定優先。
- Jackpot 真身不套用普通候選機率；它依 `attachedCardConfig.capacity.jackpot` 決定目標張數，再從當下可用的效果卡與裝備共同內容池公平、無重複抽選。唯一內容不足時全部附上，不以重複卡補滿。
- Jackpot 偽裝外殼的內容在破殼時完成自己的結算，不轉移到真身；真身以相同共用選卡模組建立新的獨立內容。
- 外掛容量、候選率、Jackpot 張數分布與扇形幾何都以 config 為準；規格不保存測試中的實際數值。

## 4. 內部隱藏裝備

- 每次建立可戰鬥的普通寶箱、Jackpot 偽裝外殼或 Jackpot 真身時，各自執行一次隱藏裝備產生流程。
- 隱藏流程先依 config 的 `none` 與各裝備稀有度機率選出結果；若結果不是 `none`，再從該稀有度目前可用的裝備池公平選取一件。因此單一攜帶者的內部隱藏裝備最多一件。
- 隱藏裝備不占用外掛卡容量、不顯示在攜帶者身上，也不受外部可見裝備的掉落率影響。
- 選取隱藏裝備時排除同一攜帶者已顯示的裝備 id，避免同一件裝備同時以可見與隱藏來源出現在同一攜帶者。
- 隱藏稀有度分布與各稀有度可用池由 config 管理，並使用可注入亂數；相同 seed 與內容狀態必須產生相同結果。

## 5. 擊破與掉落結算

普通寶箱或 Jackpot 真身死亡，以及 Jackpot 偽裝外殼被打破時，裝備流程固定為：

1. 先凍結該攜帶者尚未結算的可見裝備與內部隱藏裝備，避免換圖或銷毀 Container 後遺失資料。
2. 每張可見裝備各自依 `visibleAttachmentDropChance` 做一次掉落判定；成功者進入獎勵批次，失敗者只播放可辨識的散失／淡出，不保留槽位也不取得。
3. 內部隱藏裝備若存在，直接加入同一獎勵批次，不再套用可見裝備掉落率。
4. 對成功掉落批次原子分配目的地並保留裝備槽，再開始各張裝備的噴出與收集動畫。

- 同一來源的每件裝備只結算一次；效果卡觸發、裝備掉落與金錢噴散可由同一死亡事件並行開始。
- Jackpot 偽裝外殼被打破也執行完整裝備結算與效果卡觸發，但維持不產生金錢；外殼內容不轉移到真身。
- Jackpot 真身擁有自己新生成的可見與隱藏裝備；真身死亡時獨立結算，並正常產生 Jackpot 金錢。
- 外部可見掉落機率是裝備 config 的可調值，不依攻擊次數、傷害來源或已延後的鬆動值修正。

## 6. 裝備欄、背包與目的地保留

- 畫面下方顯示由 `initialSlotCount` 決定數量的通用裝備槽；槽位不限制 weapon、decoration、稀有度或裝備 id。
- 成功掉落批次建立時，先讀取尚未占用或保留的空槽。若同批裝備超過空槽數，先按稀有度由高至低排序，同稀有度維持批次中的穩定順序，再逐一保留槽位。
- 槽位保留必須是核心狀態的原子操作；飛行中的保留槽視為已占用，後續同時掉落不得再把另一件裝備指向同一格。
- 沒有取得槽位的裝備飛向 `src/assets/equipment/backpack.png`。本次背包容量不設上限，只作為局內未啟用裝備的收集目的地，不提供打開、整理、換裝或出售操作。
- 抵達已保留槽位的同一刻，該裝備才從 `reserved` 轉為 `equipped`、固定顯示在該槽並啟用能力；噴出、等待或飛行途中都不生效。
- 抵達背包的裝備只記錄為 `stored`，不提供任何能力。裝備欄已滿後，不替換現有裝備。
- 同一 id 可占用多個槽位；Sword 效果線性疊加，Ring 效果依第 8 節處理。

## 7. 掉落與收集動畫

- 同一擊破／破殼事件成立時，裝備與金幣同時向外噴出；裝備的收集排程必須讓它比同事件的金幣更晚抵達 HUD，形成可辨識的節奏差。
- 成功的可見裝備與存在的隱藏裝備必須以具有明顯高度的拋物線向外灑出，使用可注入初速、角度、重力與局部落地高度的逐幀運動；不得以固定短距離線性位移代替噴出。
- 裝備落地後依 config 反彈指定次數並逐次衰減水平與垂直速度，再進入停留狀態。裝備卡面與其稀有度光暈在拋射、旋轉、反彈與停留期間必須共用同一 transform。
- 裝備與金幣共用同一個純資料 burst／bounce 運動核心，但各自保有獨立 config；不得複製一套只改名稱的裝備物理。裝備拋射高度、速度、重力、落地範圍、反彈次數與速度保留率都由 config 管理。
- 裝備只有在完成拋射／反彈，且同事件金幣已完成收集與額外錯開時間後，才能由停留位置飛向已保留槽位或背包。若金幣較早完成，仍須等待裝備落地；若裝備較早落地，則在原地等待金幣事件。
- 沒有金幣流程的 Jackpot 偽裝外殼，使用 config 的 fallback 等待時間後開始收集。
- 裝備噴出、停留、飛行、錯開與 fallback 時間都使用 Pixi ticker 的 `deltaMS` 累積，不使用 `setTimeout`、`Date.now()` 或真實牆鐘。
- React HUD 只提供裝備槽與背包 icon 的 viewport 目標矩形；Pixi runtime 換算成 canvas 座標並執行逐幀動畫。React 不決定槽位分配或裝備何時生效。
- 目標位置在動畫期間改變時，runtime 使用最新合法座標平滑重定向；目標暫時不可用時保留邏輯目的地，但不得誤啟用裝備。
- 回合收尾會取消尚未抵達的收集動畫及其槽位保留；取消的裝備不啟用、不進背包，也不影響結算。

## 8. 裝備效果

### 8.1 Sword

- 每件已裝備 Sword 將 `weaponDamageBonus` 加到主武器攻擊的最終傷害；多件以加法疊加。本次手動點擊是唯一主武器來源，後續自動武器若沿用同一入口也取得相同加成。
- 加成只計入裝備完成後的新攻擊，不追溯飛行中的攻擊，也不改寫效果卡以初始武器傷害推導的既有公式。
- 加成數值只存在裝備 config，測試必須匯入同一設定。

### 8.2 Ring 的有效命中計數

- 至少一枚 Ring 已裝備後，使用玩家全域、跨目標的單一計數器累積「有效手動武器命中」。
- 只有通過每目標武器傷害間隔、確實對可受擊實體造成傷害的手動點擊才增加計數。間隔內被拒絕的點擊、效果卡傷害、Ring 追加攻擊與未造成傷害的輸入都不計數。
- 計數達到 `acceptedManualHitsPerTrigger` 時歸零，並以觸發該次命中的最終武器傷害、目標 runtime identity、目標當下場地位置與已裝備 Ring 數量建立一批追加攻擊快照；目標位置作為實體失效後繼續播放 hit 視覺的基準，之後才抵達的 Ring 不加入既有批次。
- 計數器由已裝備的 Ring 共用，不因裝備多枚而讓一次手動命中重複增加計數。

### 8.3 Ring 追加攻擊

- 每枚快照中的 Ring 產生一段追加攻擊；目標在該段結算時仍可受擊，才造成 `triggeringWeaponDamage × additionalDamageMultiplier` 傷害。第一段也必須與觸發命中分開，所有段數再以固定 `additionalHitIntervalMs` 依序結算，不得與觸發命中同時出現。
- 所有 Ring 批次共用玩家的一條序列佇列；前一批尚未結束時，新批次附加在佇列尾端，任兩段相鄰追加攻擊都維持相同固定間隔，不合併成同時傷害。
- 每段到達結算時點都必須建立向右上偏移的 `effects/hit.png` 視覺；目標仍可受擊時，該段傷害與視覺在同一 ticker 時點發生。偏移量由 config 管理，營造連擊而不改變命中座標或範圍。
- Ring 追加 hit 沿用普通手動 hit 的共用 frame texture 與動畫播放器，但建立顯示物件時套用 Ring 專用 tint，使追加段能立刻與普通命中區分。顏色在 config 以容易調整的 CSS `#RRGGBB` 字串保存，Pixi 邊界只在建立該次效果時轉成 tint number；不得在 ticker 每幀轉換，也不得為此增加 filter、mask 或重複 Sprite pass。
- 目標仍可受擊時，追加攻擊繞過每目標武器傷害間隔，但沿用唯一的傷害、裂紋、死亡、收益、效果卡與 Jackpot 結算入口；它不是手動武器命中，不增加 Ring 計數，也不能遞迴觸發新的 Ring 批次。
- 批次鎖定觸發命中的同一 runtime 實體，不得把追加攻擊轉移給其他目標。本局仍在進行時，目標死亡、離場或變成不可受擊狀態都不得取消已排入佇列的剩餘段數；每段仍按原固定間隔播放 Ring hit 視覺，但不再造成傷害、裂紋、死亡、收益、效果卡或裝備結算。找得到且仍可受擊的目標使用該段結算時的目標位置；目標失效後則使用批次保存的位置，確保一批有多少段就能看見多少段連擊動畫。
- 打破 Jackpot 偽裝外殼時 runtime 實體保持相同；該次命中建立的待結算 Ring 追加攻擊可在固定間隔後命中已揭露的 Jackpot 真身。
- 主倒數耗盡或回合收尾時取消所有未結算段數，不得在戰鬥結束後造成傷害或收益。

## 9. config 權責

執行中的裝備數值以 `src/configs/equipmentConfig.ts`、`src/configs/attachedCardConfig.ts`、`src/configs/combatConfig.ts` 與 `src/configs/animationConfig.ts` 為唯一真相。規格只固定欄位語意、公式、合法範圍與時序，不記錄測試用數值；當前平衡報告直接讀取正式 config，新報告取代舊報告，不保留過時快照。

| config 欄位 | 責任與限制 |
| --- | --- |
| `initialSlotCount` | 單局開始時建立的通用裝備槽數量；必須為非負整數 |
| `visibleAttachmentDropChance` | 每張外部可見裝備的獨立成功率；限制在有效機率範圍 |
| `hiddenDropRarityChances` | `none` 與各裝備稀有度的完整機率分布 |
| `weaponDamageBonus` | 每件 Sword 提供的固定武器傷害加成 |
| `acceptedManualHitsPerTrigger` | Ring 觸發所需的有效手動命中數；必須為正整數 |
| `additionalDamageMultiplier` | Ring 每段追加攻擊相對觸發武器傷害的倍率；必須大於零 |
| `additionalHitIntervalMs` | 觸發命中後至第一段及後續各段之間共用的固定間隔；必須大於零 |
| `additionalHitEffectOffset` | Ring 追加 hit 特效相對目標命中點的右上偏移 |
| `additionalHitEffectTintColor` | Ring 追加 hit 的 CSS `#RRGGBB` tint 字串；由 Pixi 顯示邊界在建立效果時轉換，不保存 `0x...` 數值 |
| 裝備收集動畫欄位 | 拋射角度／速度、重力、落地範圍、反彈次數／保留率、停留、比金幣晚抵達的錯開、飛行速度／時間及無金幣 fallback |
| 稀有度光暈欄位 | 由共用外掛卡 config 管理 `R`／`SR`／`SSR`／`UR` 的卡形輪廓、色彩、線寬、模糊／padding、透明度與呼吸；裝備不得另設依 id 命名的光暈欄位 |

## 10. 驗證要求

### 10.1 確定性核心測試

- 固定 seed 下，共用外掛候選、公平容量裁切、Jackpot 保證選卡與隱藏稀有度抽選可重複；隱藏裝備最多一件且不與同攜帶者可見裝備重複。
- 可見裝備掉落機率的失敗、成功與邊界結果由注入亂數控制；失敗不得保留槽位或取得裝備。
- 同一批多件掉落會原子保留不同空槽；容量不足時依規則分配，剩餘裝備進入背包，已保留槽不會被另一批重複占用。
- 裝備在飛行中不生效，抵達槽位後才生效；抵達背包不生效，回合清理會取消飛行、保留與待結算攻擊。
- Sword 重複裝備依 config 線性疊加。
- Ring 只計算有效手動武器命中；跨目標共用計數，多枚 Ring 依 config 固定間隔順序結算，傷害使用觸發命中的快照，且不遞迴。
- Ring 目標死亡、離場或不可受擊後，剩餘段數仍依序產生視覺但不造成任何遊戲結果；打破 Jackpot 偽裝外殼時可沿同一 runtime 身分命中真身；主倒數耗盡或回合收尾時才取消所有未結算段數。
- Jackpot 外殼破裂會結算可見與隱藏裝備但不產生金錢；外殼與真身內容各自只結算一次。
- 所有測試從正式 config 讀取數值，時間以參數或 `deltaMS` 注入，不依賴真實時間與隨機結果。

### 10.2 平衡與人工檢查

- Sword、Ring、裝備附著／掉落與隱藏稀有度都會改變擊殺、收益或 Jackpot 捕獲機會，完成實作前必須依[初版核心平衡驗證閘門](./progression_and_validation.md#182-初版核心平衡驗證閘門)執行受影響的核心測試與固定 seed 模擬。
- 人工確認每張裝備素材都疊在既有 normal card frame 內，附著、拋射、反彈、收集與槽位顯示期間都不會脫框。
- 人工確認裝備與效果卡共享一個可讀扇形；`N` Sword 無光暈，Ring 的 `SR` 紫色清晰外框及模糊層在附著、飛行與槽位中都與 card frame 外緣完全貼合，且與其他 `SR` 卡外觀一致。柔光不得形成較大的第二層外框、變成圓形、遮住鄰卡、被 bounds 裁切或因每幀重畫而閃爍。
- 人工確認裝備以足夠高度的拋物線灑出並清楚落地反彈，同事件的裝備仍比金幣稍晚抵達；多件裝備可同時飛往不同槽，滿槽後則飛向背包 icon。
- 人工確認裝備抵達槽位的瞬間與傷害變化一致，飛行中及背包內不會提前生效。
