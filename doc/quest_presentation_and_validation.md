# 委託呈現與驗證規格

本文件承接[主委託／次要委託系統規格](./quest_system_spec.md)，定義委託的 UI、結算整合、首輪實作範圍與驗證原則。遊戲規則入口為 [spec.md](./spec.md)。

## 1. UI / UX 規則

### 1.1 主選單

固定顯示：

- 當前主要委託。
- 主要目標物 icon。
- 對應寶箱怪 icon。
- 最多兩個次要委託。
- 次要委託剩餘 Run 數。

不要求玩家進入額外任務頁才能理解目前目標。

### 1.2 戰鬥 HUD

主要委託與次要委託只需以小型 icon 提醒，不長時間顯示完整文字。

### 1.3 結算

處理順序：

1. 顯示戰鬥收益。
2. 一般裝備依 equipment id 合併，只顯示數量與乘算後的普通出售小計，不顯示單價。
3. 次要委託物以委託者頭像與高價收購小計替代該組普通出售小計。
4. 將普通出售與委託收購合併進本局總收益。
5. 若有主要委託物，單獨播放 `MAIN REQUEST COMPLETE`。
6. 若解鎖新寶箱或新內容，緊接著顯示解鎖卡。
7. 提供明顯的「下一場」按鈕。

委託只替代符合條件項目的出售價格，不改寫普通稀有度價格 config；整個結算避免多層確認，並沿用一般裝備出售的快轉與先存檔後揭示規則。

## 2. 第一版實作範圍建議

為了驗證系統，不需要先做完整任務庫。

### 2.1 主要委託

- 1 位固定公會窗口。
- 1 隻目前最高階寶箱怪。
- 3 個主要委託物。
- 第 3 個完成後解鎖 1 隻新寶箱怪。

### 2.2 次要委託

- 2 個委託槽。
- 3～5 種次要委託模板。
- 委託單可見掉落。
- 次要委託從下一場生效。
- 約 3 Runs 期限。
- 委託物在寶箱身上可見。
- 結算自動高價交付。

### 2.3 首輪需要驗證

1. 一個主要委託平均完成幾場最舒服。
2. 一隻寶箱支撐 2、3 或 4 個主要委託最合適。
3. 玩家是否會因主要委託物出現而明顯改變目標。
4. 玩家是否願意為了打掉最新寶箱購買永久升級。
5. 次要委託期限是否增加「下一場」動力，而不是只造成壓力。
6. 委託物與 Jackpot 同時出現時，選擇是否有趣而非煩躁。
7. 結算中的分組、價格替代與自動交付是否足夠快且容易理解。

## 3. 核心設計原則

1. **主要委託負責方向，不負責時間壓力。**
2. **次要委託負責短期 urgency，但失敗不懲罰玩家。**
3. **Jackpot 負責每局高潮，不承擔全部 progression。**
4. **新寶箱怪至少支撐數個主要委託，不讓內容一局就被消耗。**
5. **委託目標盡量使用本來就會製作的裝備，不額外浪費美術。**
6. **任務物必須在場上可辨識，讓它改變 target priority。**
7. **允許高手初見成功，不設計強制失敗牆。**
8. **所有任務流程優先自動化，避免玩家管理任務清單。**
9. **完成委託應增加再開一場的慾望，而不是增加結算停留時間。**
10. **任何新委託規則都必須先回答：它是否讓玩家更想敲下一個寶箱？**
