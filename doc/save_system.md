# 存檔系統規格

本文件定義遊戲進度的 IndexedDB 持久化、版本管理、待展示解鎖、匯出／匯入與重置行為。遊戲規則入口為 [spec.md](./spec.md)，主武器持有與切換裝備見[主武器商店規格](./weapon_shop.md)，永久升級內容見[永久升級規格](./permanent_upgrades.md)，狀態分工見[前端與遊戲執行架構](./technical_architecture.md)。

## 1. 系統責任

- 存檔必須是 `src/service` 下的獨立系統。
- IndexedDB 是瀏覽器內正式進度的唯一持久化來源。
- Zustand 只保存已載入的記憶體狀態，不得直接兼任 IndexedDB adapter。
- React UI 不直接呼叫 IndexedDB；應透過存檔 service 的明確介面操作。
- Pixi runtime 不讀寫永久進度。
- 不使用 `localStorage` 保存正式遊戲進度。唯一允許的例外是像背包排序模式這類不影響遊戲結果的 UI 偏好；這類偏好不得混入進度模型。

## 2. 存檔資料範圍

初版存檔至少包含：

- 存檔 schema 版本。
- 生涯完成局數。
- 已解鎖寶箱怪識別碼。
- 待展示的解鎖提示識別碼。
- 金幣。
- 已永久持有的主武器穩定 id 集合，以及目前裝備的單一主武器 id。
- 永久升級的穩定 id 與非負整數等級；目前只包含自動攻擊解鎖、自動攻擊間隔與裝備槽升級，不保存主武器攻擊力等級。
- 其他會跨重整保留的局外進度。

不保存：

- 場上寶箱實體。
- Mimic 座標、速度、當前血量或動畫進度。
- 尚未完成單局的即時戰鬥狀態。
- React 對話框或 Pixi 顯示物件。
- 主武器攻擊力、價格、名稱與前置，以及由永久等級與 config 推導的自動攻擊毫秒數或裝備槽數。
- 背包排序模式；它只保存於目前瀏覽器的 `localStorage`，不納入 IndexedDB、匯出碼、匯入結果或 Reset。

## 3. Schema 與版本

- 每份存檔都必須帶有明確的 `schemaVersion`。
- 目前進度 schema 為版本 `5`。既有版本依序完成原有欄位補齊後遷移至版本 `3`，由 `3 → 4` 移除 `permanentUpgrades.weaponDamage`，再由 `4 → 5` 新增主武器持有與目前裝備欄位；其餘生涯局數、解鎖、待展示提示、金幣、最近一局結果與仍存在的永久升級等級全部保留。
- `3 → 4` 遷移不退還舊主武器攻擊力升級曾花費的金幣，也不把舊等級換算成其他升級；新 schema、匯出資料、UI 與戰鬥快照都不得保留相容欄位或繼續套用舊傷害加成。
- `4 → 5` 遷移固定讓既有玩家持有並裝備 `weaponConfig.initialWeaponId` 對應的旅行者木槌，不免費贈送兩把商店武器，也不依舊金幣、永久等級或局數猜測購買狀態。
- 版本 `5` 的 `ownedWeaponIds` 必須無重複、包含初始武器且每個 id 都存在於正式 definitions；`equippedWeaponId` 必須同時存在於 definitions 與持有集合。
- IndexedDB 資料庫升級與遊戲存檔 schema 遷移是兩個明確步驟，不得只依賴資料庫版本暗示資料格式。
- 新版本讀取舊存檔時，先驗證再依序遷移至目前版本。
- 不支援的未來版本不得被舊版遊戲覆寫。
- 遷移失敗不得靜默重置進度；錯誤需包含目前版本、目標版本與失敗階段，並顯示可理解的恢復選項。

## 4. 載入流程

1. 應用啟動後，XState 進入存檔載入狀態。
2. Save service 開啟 IndexedDB 並讀取目前存檔。
3. 沒有存檔時建立包含 `normal` 的初始進度。
4. 有存檔時驗證 schema 並執行必要遷移。
5. 將有效進度放入 Zustand。
6. 若有待展示解鎖提示，先進入提示流程；否則進入可開始遊戲的狀態。

載入完成前不得開始正式單局或用預設值覆蓋尚未讀完的進度。

## 5. 寫入時機與一致性

至少在下列事件後寫入：

- 完成一局並計算生涯局數、收益與新解鎖。
- 玩家確認解鎖提示。
- 玩家購買永久升級。
- 玩家購買或切換裝備主武器。
- 成功匯入另一份進度。
- 執行全部進度重置。

### 5.1 單局結算

- 單局收尾先依成功取得裝備的不可變快照計算自動出售收益；戰鬥收益與出售收益合併後的本局總收益是本次唯一可加入玩家金幣的數字。
- 本局結果、總收益入帳、局數增加、新解鎖與待展示提示必須作為同一份一致進度寫入，不得先寫戰鬥收益再用第二次寫入補上出售收益。
- 最近一局結果快照保留戰鬥收益、裝備出售收益、最終總收益與依 equipment id 分組的出售明細，供結算 UI 顯示；局內裝備 instance 與動畫狀態仍不得寫入存檔。
- 存檔寫入成功後才能進入結算揭示；逐列動畫、點擊快轉或 UI 重掛載不得再次修改金幣。
- 寫入成功後才能顯示新解鎖提示。
- 若寫入失敗，不得假裝解鎖已安全保存；UI 應顯示可重試且包含操作上下文的錯誤。

### 5.2 解鎖提示

- 顯示提示前，存檔中已包含該解鎖與「待展示」狀態。
- 玩家確認後，移除對應待展示識別碼並再次寫入。
- 如果確認後的寫入失敗，提示可在下次啟動再次出現，但不得遺失已解鎖內容。

### 5.3 永久升級購買

- 購買前由永久升級 service 依正式 config 驗證升級 id、目前等級、最高級、前置條件、價格與玩家金幣，不接受 UI 傳入的價格或下一級效果。
- 扣除金幣與提高指定升級等級必須形成同一份下一進度並一次寫入 IndexedDB；寫入成功後才更新 Zustand 與購買成功顯示。
- 寫入失敗、金幣不足、前置條件不符或已達最高級時，正式進度與記憶體狀態都維持購買前內容。
- 自動攻擊解鎖與間隔等級分開保存；解鎖前不得存在大於 `0` 的間隔等級。
- 裝備槽只保存同一條升級線的等級。等級 `0`／`1` 目前分別解析為 2／3 格；未來加入第 4 格時沿用等級 `2`，不得新增 `hasThirdSlot`、`hasFourthSlot` 或保存衍生槽位數。
- 永久升級購買 service 不接受 `weaponDamage` 作為永久升級 id；主武器交易只接受 weapon id 並走下一節的獨立流程。

### 5.4 主武器購買與切換裝備

- 武器 service 依正式 config 驗證武器 id、持有狀態、前置、價格與玩家金幣，不接受 UI 傳入價格、傷害或前置。
- 購買成功必須在同一份下一進度中扣除金幣、加入 `ownedWeaponIds` 並把 `equippedWeaponId` 切換為新武器；寫入成功後才更新 Zustand 與商店狀態。
- 免費切換只能選擇已持有武器，同樣先保存完整下一進度，成功後才更新記憶體狀態。
- 金幣不足、前置不符、已持有、未知 id、未持有武器切換或保存失敗都不得留下部分交易。

## 6. 進度匯出

玩家可將目前完整進度輸出成一段便於複製的編碼字串。

匯出內容必須包含：

- 匯出格式版本。
- 完整存檔資料。
- 完整性校驗值。

編碼規則：

- 將通過 schema 驗證的存檔序列化為穩定資料格式。
- 使用可安全處理 UTF-8 的 Base64 編碼，呈現為使用者看到的「亂碼」。
- 加入校驗值，用來偵測複製遺漏、內容損壞或格式錯誤。
- 編碼與校驗只保證完整性，不宣稱能防止玩家自行解碼修改；純前端存檔不具可靠防作弊能力。
- 匯出不改變目前進度。

## 7. 進度匯入

匯入流程：

1. 接收玩家貼上的編碼字串。
2. 解碼並檢查匯出格式版本。
3. 驗證校驗值。
4. 驗證存檔 schema 並執行支援的遷移。
5. 顯示「將完整取代目前進度」的確認 UI。
6. 確認後以完整且一致的寫入取代目前 IndexedDB 進度。
7. 寫入成功後重新載入 Zustand 與應用流程。

任何解碼、校驗、schema 或遷移錯誤都不得覆寫目前進度。錯誤訊息需說明失敗階段，但不得把整份進度內容輸出到錯誤記錄。

## 8. 重置全部進度

- 設定介面提供 Reset 按鈕。
- Reset 必須先顯示明確確認 UI，說明會刪除全部遊戲進度且無法從本機自動復原。
- 玩家確認後，清除目前正式進度並建立全新的初始存檔。
- 初始存檔只解鎖 `normal`，只持有並裝備旅行者木槌；生涯完成局數、貨幣、升級與待展示提示全部回到初始值。
- 重置成功後重新載入 Zustand 與應用流程，不保留舊的 Pixi 場上實體。
- 重置失敗不得只清除記憶體狀態；UI 應保留目前可用進度並提供錯誤與重試方式。

## 9. 錯誤處理

- 不吞掉 IndexedDB、序列化、校驗、遷移或寫入錯誤。
- 每個錯誤包含足以定位的操作名稱，例如載入、結算寫入、解鎖確認、匯入或重置。
- 可預期的無效匯入碼使用一般錯誤提示，不以例外流程破壞應用。
- 儲存空間不足、權限或資料庫不可用時，禁止開始會產生無法保存永久結果的操作，或明確告知玩家目前進度無法安全保存。
- 不得因單次讀取錯誤自動建立新存檔並覆蓋可能仍可恢復的資料。

## 10. 行為驗證

至少驗證：

- 新使用者建立正確初始存檔。
- 完成第一、二局後，局數、解鎖與待展示提示原子性一致。
- 提示前關閉遊戲，重新開啟後能補播。
- 確認提示後不會再次正常播放。
- 匯出再匯入可還原相同進度。
- 損壞、截斷、錯誤校驗或不支援版本不會覆寫目前存檔。
- Reset 確認後回到只解鎖 `normal` 的初始狀態。
- 模擬 IndexedDB 失敗時，不會吞錯或讓 Zustand 與正式存檔假裝同步。
- 各永久升級可依序購買並在重新載入後保留；金幣不足、錯誤前置與最高級購買不扣款，寫入失敗不留下部分交易。
- 匯出／匯入保留永久升級等級，重置則全部回到等級 `0`；裝備槽等級在相同欄位下可向後擴充到未來第 4 格。
- 版本 `3` 存檔遷移至版本 `4` 後會移除 `weaponDamage`、不退款並保留其他進度；重新匯出時不再出現該欄位，舊等級也不影響戰鬥傷害。
- 版本 `4` 存檔遷移至版本 `5` 後只持有並裝備初始武器，保留其他全部進度；匯出／匯入保留持有集合與目前裝備，Reset 回到只有初始武器。
- 武器購買的扣款、持有與自動裝備原子一致；免費切換只能選擇已持有 id，重新載入後結果正確，任何失敗不會讓 Zustand 與 IndexedDB 分歧。
