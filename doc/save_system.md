# 存檔系統規格

本文件定義遊戲進度的 IndexedDB 持久化、版本管理、待展示解鎖、匯出／匯入與重置行為。遊戲規則入口為 [spec.md](./spec.md)，狀態分工見[前端與遊戲執行架構](./technical_architecture.md)。

## 1. 系統責任

- 存檔必須是 `src/service` 下的獨立系統。
- IndexedDB 是瀏覽器內正式進度的唯一持久化來源。
- Zustand 只保存已載入的記憶體狀態，不得直接兼任 IndexedDB adapter。
- React UI 不直接呼叫 IndexedDB；應透過存檔 service 的明確介面操作。
- Pixi runtime 不讀寫永久進度。
- 不使用 `localStorage` 保存正式遊戲進度。

## 2. 存檔資料範圍

初版存檔至少包含：

- 存檔 schema 版本。
- 生涯完成局數。
- 已解鎖寶箱怪識別碼。
- 待展示的解鎖提示識別碼。
- 金幣與特殊素材。
- 永久升級及其等級。
- 其他會跨重整保留的局外進度。

不保存：

- 場上寶箱實體。
- Mimic 座標、速度、當前血量或動畫進度。
- 尚未完成單局的即時戰鬥狀態。
- React 對話框或 Pixi 顯示物件。

## 3. Schema 與版本

- 每份存檔都必須帶有明確的 `schemaVersion`。
- IndexedDB 資料庫升級與遊戲存檔 schema 遷移是兩個明確步驟，不得只依賴資料庫版本暗示資料格式。
- 新版本讀取舊存檔時，先驗證再依序遷移至目前版本。
- 不支援的未來版本不得被舊版遊戲覆寫。
- 遷移失敗不得靜默重置進度；錯誤需包含目前版本、目標版本與失敗階段，並顯示可理解的恢復選項。

## 4. 載入流程

1. 應用啟動後，XState 進入存檔載入狀態。
2. Save service 開啟 IndexedDB 並讀取目前存檔。
3. 沒有存檔時建立包含 `normal` 的初始進度。
4. 有存檔時驗證 schema 並執行必要遷移。
5. 將有效進度放入 Zustand。
6. 若有待展示解鎖提示，先進入提示流程；否則進入可開始遊戲的狀態。

載入完成前不得開始正式單局或用預設值覆蓋尚未讀完的進度。

## 5. 寫入時機與一致性

至少在下列事件後寫入：

- 完成一局並計算生涯局數、收益與新解鎖。
- 玩家確認解鎖提示。
- 玩家購買永久升級。
- 成功匯入另一份進度。
- 執行全部進度重置。

### 5.1 單局結算

- 單局收尾先依成功取得裝備的不可變快照計算自動出售收益；戰鬥收益與出售收益合併後的本局總收益是本次唯一可加入玩家金幣的數字。
- 本局結果、總收益入帳、局數增加、新解鎖與待展示提示必須作為同一份一致進度寫入，不得先寫戰鬥收益再用第二次寫入補上出售收益。
- 最近一局結果快照保留戰鬥收益、裝備出售收益、最終總收益與依 equipment id 分組的出售明細，供結算 UI 顯示；局內裝備 instance 與動畫狀態仍不得寫入存檔。
- 存檔寫入成功後才能進入結算揭示；逐列動畫、點擊快轉或 UI 重掛載不得再次修改金幣。
- 寫入成功後才能顯示新解鎖提示。
- 若寫入失敗，不得假裝解鎖已安全保存；UI 應顯示可重試且包含操作上下文的錯誤。

### 5.2 解鎖提示

- 顯示提示前，存檔中已包含該解鎖與「待展示」狀態。
- 玩家確認後，移除對應待展示識別碼並再次寫入。
- 如果確認後的寫入失敗，提示可在下次啟動再次出現，但不得遺失已解鎖內容。

## 6. 進度匯出

玩家可將目前完整進度輸出成一段便於複製的編碼字串。

匯出內容必須包含：

- 匯出格式版本。
- 完整存檔資料。
- 完整性校驗值。

編碼規則：

- 將通過 schema 驗證的存檔序列化為穩定資料格式。
- 使用可安全處理 UTF-8 的 Base64 編碼，呈現為使用者看到的「亂碼」。
- 加入校驗值，用來偵測複製遺漏、內容損壞或格式錯誤。
- 編碼與校驗只保證完整性，不宣稱能防止玩家自行解碼修改；純前端存檔不具可靠防作弊能力。
- 匯出不改變目前進度。

## 7. 進度匯入

匯入流程：

1. 接收玩家貼上的編碼字串。
2. 解碼並檢查匯出格式版本。
3. 驗證校驗值。
4. 驗證存檔 schema 並執行支援的遷移。
5. 顯示「將完整取代目前進度」的確認 UI。
6. 確認後以完整且一致的寫入取代目前 IndexedDB 進度。
7. 寫入成功後重新載入 Zustand 與應用流程。

任何解碼、校驗、schema 或遷移錯誤都不得覆寫目前進度。錯誤訊息需說明失敗階段，但不得把整份進度內容輸出到錯誤記錄。

## 8. 重置全部進度

- 設定介面提供 Reset 按鈕。
- Reset 必須先顯示明確確認 UI，說明會刪除全部遊戲進度且無法從本機自動復原。
- 玩家確認後，清除目前正式進度並建立全新的初始存檔。
- 初始存檔只解鎖 `normal`，生涯完成局數、貨幣、升級與待展示提示全部回到初始值。
- 重置成功後重新載入 Zustand 與應用流程，不保留舊的 Pixi 場上實體。
- 重置失敗不得只清除記憶體狀態；UI 應保留目前可用進度並提供錯誤與重試方式。

## 9. 錯誤處理

- 不吞掉 IndexedDB、序列化、校驗、遷移或寫入錯誤。
- 每個錯誤包含足以定位的操作名稱，例如載入、結算寫入、解鎖確認、匯入或重置。
- 可預期的無效匯入碼使用一般錯誤提示，不以例外流程破壞應用。
- 儲存空間不足、權限或資料庫不可用時，禁止開始會產生無法保存永久結果的操作，或明確告知玩家目前進度無法安全保存。
- 不得因單次讀取錯誤自動建立新存檔並覆蓋可能仍可恢復的資料。

## 10. 行為驗證

至少驗證：

- 新使用者建立正確初始存檔。
- 完成第一、二局後，局數、解鎖與待展示提示原子性一致。
- 提示前關閉遊戲，重新開啟後能補播。
- 確認提示後不會再次正常播放。
- 匯出再匯入可還原相同進度。
- 損壞、截斷、錯誤校驗或不支援版本不會覆寫目前存檔。
- Reset 確認後回到只解鎖 `normal` 的初始狀態。
- 模擬 IndexedDB 失敗時，不會吞錯或讓 Zustand 與正式存檔假裝同步。
