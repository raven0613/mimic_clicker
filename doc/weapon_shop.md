# 主武器商店規格

本文件承接 [spec.md](./spec.md) 的主武器與局外成長規則，定義主武器的階段性購買、永久持有、局外裝備、單局戰鬥快照、數值階梯、商店呈現與驗證要求。懸停自動攻擊及裝備槽仍見[永久升級規格](./permanent_upgrades.md)，金幣收入與共通平衡閘門見[局外成長、內容與驗證規格](./progression_and_validation.md)，持久化與遷移見[存檔系統規格](./save_system.md)。

## 1. 設計目標與範圍

主武器商店負責建立可預期的中長期存錢目標與明顯的火力躍升，使用以下重複節奏：

> 最新高價寶箱需要約 5 次無裝備武器命中 → 玩家存錢購買下一階主武器 → 同一寶箱降為約 2 次命中 → 更高階寶箱成為新的高價難打目標

- 主武器成長採少量、完整的傷害階段，不重新加入 `+5` 類可重複購買的微幅永久攻擊力等級。
- 本次三把主武器都只改變基礎攻擊力，不加入雙擊、範圍、追蹤、破甲或其他獨立攻擊機制；玩法組合仍主要來自局內裝備卡與效果卡。
- 武器商店與永久升級是同一個局外金幣經濟中的不同消費項目，但不把武器偽裝成永久升級等級，也不共用容易混淆的等級存檔欄位。
- 玩家可以為下一把武器存錢，也可以先購買懸停自動攻擊或第三裝備槽；這個機會成本是局外成長的主要選擇。
- 本次商店使用純文字卡片，不新增武器圖示、攻擊動畫或武器專屬特效素材。

目前不做：

- 武器升級、強化、鍛造、分解、出售或退款。
- 戰鬥中途換武器。
- 武器隨機輪替、限時折扣、每日商店或隱藏商品。
- 同時裝備多把主武器。
- 武器專屬攻速、每目標傷害間隔或特殊攻擊行為。

## 2. 正式武器定義與 config 權責

### 2.1 初始內容

| 穩定 id | 顯示名稱 | 基礎攻擊力 | 價格 | 前置武器 | 初始狀態 |
| --- | --- | ---: | ---: | --- | --- |
| `travelerHammer` | 旅行者木槌 | `10` | `0` | 無 | 新存檔永久持有並裝備 |
| `lockbreakerHammer` | 破鎖鐵鎚 | `25` | `3,000 G` | `travelerHammer` | 可購買 |
| `runicSiegeHammer` | 符文破城鎚 | `65` | `12,000 G` | `lockbreakerHammer` | 前置完成後可購買 |

### 2.2 單一數值來源

- 新增 `weaponConfig` 作為全部主武器定義與 `initialWeaponId` 的唯一正式來源。
- 每筆定義至少包含穩定 `id`、`displayName`、正整數 `baseDamage`、非負整數 `priceGold` 與 `requiredWeaponId`；初始武器的前置為空且價格為 `0`。
- 顯示順序可以沿用 definitions 順序，但購買資格必須解析 `requiredWeaponId`，不得以陣列索引或 UI 位置暗示前置。
- 武器 id 型別、存檔驗證與商店清單應由正式 definitions 推導，不在 UI、購買 service、測試或模擬另建一份 id 清單。
- UI 不傳入或決定價格、攻擊力與前置條件；購買 service 只接受武器 id，再自行讀取正式 config 驗證。
- 移除 `combatConfig.initialWeaponDamage`。效果卡需要的初始武器基準改由 `weaponConfig.initialWeaponId` 對應定義取得，避免 `10` 存在兩份可能分歧的正式來源。
- 單純調整名稱、價格、武器攻擊力或怪物血量／收益時只修改各自 config；若不改變本文件的規則與目標門檻，不需在其他模組複寫數值。
- 新增另一把純傷害武器時，應只需新增 config 定義並由既有商店、購買、裝備、存檔與戰鬥快照流程處理；只有新增不同攻擊行為才需要新的戰鬥程式。

## 3. 持有、前置與裝備規則

- 新存檔永久持有 `travelerHammer`，且目前裝備武器為 `travelerHammer`。
- 三把武器從一開始都顯示在商店中，讓玩家能看見目前與長期目標；未滿足前置的武器仍顯示名稱、攻擊力與價格，但標示所需前置且不可購買。
- 玩家只有在永久持有 `requiredWeaponId` 時才能購買該武器；持有前置不要求目前正裝備前置武器。
- 購買成功後永久加入持有集合，並自動成為目前裝備武器。
- 已持有武器不可重複購買；重複請求不得扣款或改變裝備狀態。
- 玩家可在局外自由切換裝備任何已持有武器，不收費、不消耗道具；未持有或不存在的武器不得裝備。
- 同一時間只有一個目前裝備武器。裝備較低階武器是允許且可逆的玩家選擇，不自動出售或刪除舊武器。
- 購買與切換裝備只允許在可開始下一局的局外狀態進行；正在遊玩、保存結算、展示結算或解鎖提示時不接受交易或切換。

## 4. 交易、保存與失敗處理

- 購買前由武器 service 驗證武器 id、是否已持有、前置、價格與目前金幣，不信任 UI 傳入的衍生資料。
- 扣除金幣、加入持有集合與切換目前裝備武器必須形成同一份新進度，並以一次一致寫入保存。
- 寫入 IndexedDB 成功後才更新 Zustand 與商店成功狀態；保存失敗時不得顯示已購買、只扣款、只持有或只切換裝備。
- 免費切換裝備同樣必須先形成合法的新進度並保存成功後才更新記憶體狀態。
- 金幣不足、前置未完成、已持有、未知 id 或非法切換屬於正常拒絕結果；進度保持原樣，不使用例外取代正常狀態。
- 保存失敗必須提供包含購買或切換武器 id 的錯誤上下文，並保留原本可再次操作的進度。

## 5. 單局戰鬥套用

- 開始一局時，從目前裝備武器建立不可變的武器快照，至少包含武器 id 與基礎攻擊力；本局不再讀取局外商店狀態。
- 手動攻擊與懸停自動攻擊使用同一份已裝備武器基礎攻擊力。
- 每件已裝備 Sword 仍依 `equipmentConfig.sword.weaponDamageBonus` 提供固定加成；最終武器傷害為「主武器基礎攻擊力 + 已裝備 Sword 數量 × 固定加成」。
- Ring 仍快照觸發該次有效手動命中的最終武器傷害，因此會自然取得目前主武器與 Sword 的結果。
- Jackpot 偽裝外殼與真身都接受同一份主武器快照；不建立 Jackpot 專用武器公式。
- `combatConfig.minimumWeaponDamageIntervalPerTargetMs` 仍是所有主武器攻擊共用的技術准入限制，不因武器階段改變，也不是可購買攻速。
- 切換主武器只改變武器快照的基礎傷害，不改變共用 `effects/hit.png` 的來源辨識：手動置中於實際點擊位置、懸停自動攻擊位於最新游標左下、Ring 位於觸發批次的點擊位置右上；偏移與 tint 由各自功能 config 決定。
- 落雷、隕石與龍捲風繼續由初始武器 `travelerHammer` 的 `10` 點基準乘上各自倍率推導傷害；切換主武器、Sword 與自動攻擊間隔都不放大效果卡。
- 局外購買或切換裝備不回溯影響已開始的單局；下一局才使用新的武器快照。

## 6. 怪物強度、收益與武器門檻

### 6.1 第一輪誇張測試值

| 寶箱怪 | 最大血量 | 基礎收益 | 生成權重 |
| --- | ---: | ---: | ---: |
| `normal` | `20` | `5 G` | `65` |
| `rare1` | `50` | `18 G` | `25` |
| `rare2` | `125` | `50 G` | `10` |

- 寶箱數值仍只由 `mimicConfigs` 提供；本表定義第一輪實作要寫入 config 的起始候選，之後依正式模擬與人工遊玩直接調整 config。
- `rare1` 與 `rare2` 的高收益必須補償其在對應舊武器階段需要的額外注意與命中，不可讓最新高階寶箱的單位操作回報低於已熟練處理的上一階寶箱。
- `rare2` 仍維持高於一張初始隕石卡全部隕石總傷害的耐久錨點定位；提高主武器階段不得同步放大效果卡來抹除這個差異。
- `rare2` 在玩家尚未購買破鎖鐵鎚時會是約 13 擊的提前可見高額目標。它不是強制擊破條件，玩家可以硬打、先用效果削血或放過並存錢；其低生成權重與高收益應讓這個選擇成為期待，不是全場磨血。

### 6.2 無 Sword 的明確擊殺門檻

| 寶箱怪 | 旅行者木槌 `10` | 破鎖鐵鎚 `25` | 符文破城鎚 `65` |
| --- | ---: | ---: | ---: |
| `normal` | 2 擊 | 1 擊 | 1 擊 |
| `rare1` | 5 擊 | 2 擊 | 1 擊 |
| `rare2` | 13 擊 | 5 擊 | 2 擊 |

- 擊殺命中數只依 `ceil(最大血量 ÷ 當次最終武器傷害)` 推導，不在 runtime 保存另一份命中數設定。
- 這組 `5 → 2` 是階段性成長的驗證點，不採用 `5 → 4 → 3` 的微幅測試路徑；若人工遊玩仍無感，下一輪應直接測試另一個明顯門檻，而不是逐點增加攻擊力。
- Sword、Ring、效果卡、事前削血與連鎖可以讓實際命中數更低，這是局內成長的預期結果；正式門檻表只比較沒有局內裝備與效果介入的主武器基準。

### 6.3 最新目標的操作回報

| 使用武器 | 已熟練目標 | 基礎收益／必要命中 | 最新高價目標 | 基礎收益／必要命中 |
| --- | --- | ---: | --- | ---: |
| 旅行者木槌 | `normal` | `5 ÷ 2 = 2.5 G` | `rare1` | `18 ÷ 5 = 3.6 G` |
| 破鎖鐵鎚 | `rare1` | `18 ÷ 2 = 9 G` | `rare2` | `50 ÷ 5 = 10 G` |

- 最新目標不只總獎金較高；在需要更多命中的舊武器階段，每次必要命中的基礎收益也必須高於已熟練目標，讓集中處理強怪不是純粹降低賺錢效率。
- 第一輪候選讓 `rare1` 單隻基礎收益為 `normal` 的 `3.6` 倍，`rare2` 為 `rare1` 的約 `2.78` 倍；之後調 config 仍須讓單隻最新目標至少明顯高於前一階，而不是只用生成稀有度製造期待。
- 這個比較只衡量基礎戰鬥收益，不把裝備出售、效果連鎖或 Jackpot 獎勵灌入強怪價值；完整單局經濟仍以批次模擬為準。

## 7. 商店介面

- 武器商店與永久升級同時位於可開始下一局的主選單層級，兩者是分開且清楚命名的區塊，不建立多層商店導覽。
- 商店固定顯示所有目前定義武器，每張文字卡至少顯示名稱、基礎攻擊力、價格與目前狀態。
- 狀態與主要操作固定區分為：`目前裝備`、`裝備`、`購買`、`金幣不足`、`需要前置武器`。
- 初始武器不顯示可購買價格按鈕；已持有但未裝備的武器顯示免費「裝備」。
- 未持有且符合前置的武器依玩家金幣決定顯示「購買」或「需要 N G」；未符合前置時優先顯示前置名稱，不讓金幣充足誤導成可以跳階購買。
- 交易或切換裝備保存期間停用全部武器操作，避免重複送出；永久升級商店與開始下一局按鈕是否一併暫停，依共用保存中的一致性狀態處理。
- 購買成功後卡片立即變成「目前裝備」，總金幣同步更新，並清楚提示下一局生效。
- 開始下一局仍是局外畫面的主要操作，不強迫玩家購買、切換或逐張確認武器。

## 8. 存檔資料

- 進度保存 `ownedWeaponIds` 與 `equippedWeaponId`，不保存武器攻擊力、價格、顯示名稱或前置等可由 config 推導的資料。
- 持有集合不得重複，必須包含初始武器；目前裝備 id 必須存在於持有集合與正式 weapon definitions。
- schema 版本與舊存檔遷移依[存檔系統規格](./save_system.md)執行。既有版本遷移後取得並裝備初始武器，其他金幣、局數、解鎖、結算與永久升級進度全部保留。
- 匯出、匯入、重整與 Reset 都必須保留或正確重建持有與目前裝備狀態。

## 9. 驗證要求

### 9.1 確定性核心測試

- weapon definitions 的 id 唯一，初始 id 存在且價格為 `0`；所有非初始武器價格與攻擊力為正整數，前置 id 存在，前置鏈無循環。
- 新存檔只持有並裝備初始武器；舊 schema 遷移、匯出／匯入與 Reset 結果一致。
- 三把武器從一開始都能建立商店卡，前置未完成時不可購買但仍顯示正式名稱、攻擊力與價格。
- 金幣不足、前置未完成、已持有與未知 id 都不改變金幣、持有集合或目前裝備。
- 成功購買原子完成扣款、持有與自動裝備；保存失敗不留下部分交易。
- 只能裝備已持有武器，成功切換可重新載入；進行中的單局不因局外狀態改變而更新快照。
- 手動與自動攻擊取得同一基礎傷害，Sword 固定加成與 Ring 快照順序正確；三種武器都沿用相同的游標原點／偏移／tint 命中特效規則，效果卡則始終使用初始武器基準且不播放武器 hit。
- 無 Sword 時的三種寶箱命中數直接由正式 weapon 與 mimic config 推導，並符合第 6.2 節門檻。

### 9.2 批次平衡模擬

- 武器加入後必須依[初版核心平衡驗證閘門](./progression_and_validation.md#182-初版核心平衡驗證閘門)重跑完整受影響矩陣並更新唯一的[當前核心平衡報告](./balance_report.md)。
- 矩陣至少涵蓋三種武器、三個寶箱解鎖池、無裝備與代表 Sword／Ring 配置、手動操作模型、懸停自動攻擊各階段、第三槽及 Jackpot 結果。
- 同一全解鎖池與同一操作模型下，升階武器的平均戰鬥收益必須單調提高；破鎖鐵鎚相對旅行者木槌、符文破城鎚相對破鎖鐵鎚的增幅都必須達到具名目標區間，未建立前只能標記為待校準。
- 最新高價目標相對已熟練目標的單隻基礎收益倍數及「基礎收益 ÷ 無裝備必要命中」都必須依正式 config 輸出；不得只驗證總收益隨血量上升。
- 購買路線至少比較優先存第一把武器、先買懸停／第三槽、混合購買與一路存第二把武器；需記錄每個武器里程碑的平均局數與分位數，不能只用價格除以單局平均收益。
- 第一把武器應是早期可看見並能實際接近的目標；第二把必須在第一把提高收入後仍形成明顯更遠的目標。暫定購買節奏為直存第一把約 4～8 局、持有第一把後再取得第二把約 8～16 局，正式上下限存入平衡 config。
- 驗證高傷害與 Sword／Ring 不會造成重複死亡、負血量收益、同一目標重複結算、Jackpot 流程無法進入／收尾或自動攻擊完全排除手動價值。
- 怪物血量、收益與武器傷害調整後，生成占比、擊破數、總收益、裝備出售占比、效果連鎖、低密度補場、Jackpot 獎勵與購買時程仍須通過共通門檻；不得只確認命中數表正確。

### 9.3 人工體感

- 玩家第一次看到 `rare1` 時是否感覺它難打但值得處理，購買破鎖鐵鎚後是否能不看數字就察覺由 5 擊降到 2 擊。
- 持有破鎖鐵鎚時，`rare2` 是否接手成為需要集中點擊或先用效果削血的高價目標；購買符文破城鎚後由 5 擊降到 2 擊是否形成第二次明顯力量高峰。
- 玩家是否能在商店立即辨認目前裝備、下一把武器、價格與前置，並把下一把武器視為再開一局的目標，而不是誤認為另一條微幅升級。
- 高階武器提高收入後，下一個價格是否仍讓玩家感到正在接近，而不是立刻買完或遠到看不見進度。
- 純文字商店在沒有武器圖片時是否仍能清楚傳達階段與力量差異；若資訊清楚，不因缺少圖片阻擋本次驗證。
