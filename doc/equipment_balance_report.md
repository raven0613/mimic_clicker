# 裝備系統暫定平衡報告

本報告承接[局外成長、內容與驗證規格](./progression_and_validation.md)的初版核心平衡驗證閘門，記錄 `equipment-system-v10` 對共用外掛卡池、Sword、Ring、可見／隱藏裝備、拋射反彈與局內目的地分配的固定 seed 模擬結果。加入裝備前的基準仍保留於[落雷與隕石效果卡暫定平衡報告](./effect_card_balance_report.md)，但不得取代本報告。

## 模擬版本與案例矩陣

- config 版本：`equipment-system-v10`。
- 固定 seed：`11`、`29`、`47`、`83`、`131`、`197`、`263`、`347`、`431`、`557`、`683`、`809`。
- 3 種解鎖生成池 × 3 種點擊速度 × 3 種命中率 × 4 種 Jackpot 路徑 × 6 種裝備 loadout × 12 個 seed。
- loadout 包含：未裝備、單 Sword、單 Ring、重複 Sword、重複 Ring、Sword 與 Ring 混裝。
- 合計 `7,776` 個可重複案例，全部可正常收尾。

模擬直接讀取正式 config。外掛卡候選會先共同抽選並共用容量，隱藏裝備獨立抽選；可見裝備只在對應攜帶者被擊破後依正式掉落率判定，隱藏裝備則直接進入同一批次。裝備目的地使用正式 `EquipmentState` 原子保留規則。一般怪與 Jackpot 真身的啟用時間會分別以 runtime 共用的金幣運動及正式裝備拋射／反彈運動逐幀推進，等裝備完成落地停留且同事件金幣全部完成後，再加上裝備收集飛行時間；Jackpot 偽裝因不噴金錢，改以裝備落地停留與無金幣 fallback 中較晚者為準。這是以單一事件完整金幣量及 `maximumFrameDeltaMs` 推進的保守時序模型，不模擬多事件重疊時 runtime 的並行金幣容量裁切；實機在容量已滿時，同事件可能更早完成。

控制 loadout 在每個案例開始時已裝備，用來比較 Sword 與 Ring 的戰鬥影響。局內新掉落會依實際到達時間完成槽位保留並立即生效，後續手動攻擊會讀取當下裝備傷害與 Ring 狀態；因此未裝備或單裝開局也可能在同一局取得其他裝備。Jackpot 偽裝與真身共用同一 runtime identity，排隊中的 Ring 追加段可在打破偽裝後依規則命中真身。

## 正式 config 快照

- 初始通用槽位：`2`。
- 可見裝備獨立成功率：`85%`。
- 隱藏結果分布：none `88%`、normal `10%`、SR `2%`。
- Sword：候選率 `7%`，每件武器傷害 `+5`。
- Ring：候選率 `3%`；每 `5` 次有效手動命中排入追加攻擊；每段 `100%` 觸發武器傷害；固定間隔 `200 ms`。
- 裝備噴出：角度 `-0.72π`～`-0.28π`、初速 `430`～`590 px/s`、重力 `880 px/s²`、落地偏移 `72`～`132 px`、反彈 `2`～`3` 次、垂直速度保留率 `0.40`～`0.52`、水平速度保留率 `0.72`、落地停留 `120`～`190 ms`。
- 裝備收集：金幣完成後錯開 `140 ms`、無金幣 fallback `900 ms`、飛行 `520 ms`。

## 判定與限制

`equipment-system-v10` 通過目前具名的自動化暫定目標：完整矩陣可重複、所有案例收尾、既有生成與收益趨勢仍合法、兩種裝備均能產生與掉落，Sword 疊加及 Ring 延遲追加傷害也有實際輸出。

自動化結果不能取代人工體感。仍需在實際遊戲中確認裝備素材全程位於共用卡框內、Ring 清晰外框及模糊層的基準卡形完全貼合 card frame 且只有柔光自然延伸、失敗散失、足夠高度的拋射反彈、同批分飛、比金幣晚抵達、抵達瞬間生效，以及 `200 ms` 右上偏移且帶專用 tint 的連擊是否清楚。若依人工測試調整任何結果相關 config，必須重跑同一案例矩陣並更新本報告。
