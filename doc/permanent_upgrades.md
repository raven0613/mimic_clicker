# 永久升級規格

本文件承接 [spec.md](./spec.md) 的局外成長規則，定義目前採用的永久升級、購買順序、戰鬥套用邊界、槽位擴充方式與驗證要求。局外經濟、結算及共通平衡閘門見[局外成長、內容與驗證規格](./progression_and_validation.md)，存檔交易見[存檔系統規格](./save_system.md)。

## 1. 設計目標與範圍

目前只採用兩條短成長線：

1. 解鎖懸停自動攻擊，再提升自動攻擊間隔 1～3 級。
2. 購買一次「裝備槽 III」里程碑，使基礎 2 格提升為 3 格。

- 兩條成長線使用金幣購買，彼此沒有跨線前置條件；只有自動攻擊間隔必須先解鎖懸停自動攻擊。
- 介面以兩條短線或兩張升級卡呈現，不保留已移除的主武器微幅攻擊力升級，也不建立散射狀大型技能樹、互斥分支或總投資點數門檻。
- 升級不是結算的強制步驟。玩家可直接開始下一局，也可在幾秒內完成購買後再開始。
- 初始效果值、價格與購買節奏依第 6 節執行，實作時只由 `permanentUpgradeConfig` 提供。
- 初版接受玩家第一局結算後可能沒有永久升級可買；第一局完成仍會解鎖 `rare1`，局內裝備與新寶箱內容負責提供前段的小型成長與變化。

目前不做：

- 主武器微幅攻擊力升級。
- 手動攻擊速度或每目標武器傷害間隔成長。
- 個別裝備卡升級、裝備效果分類共通升級。
- 可見裝備掉落率、裝備回收率或稀有度升級。
- 起始時間、效果卡、Luck／掉寶、Jackpot 或特殊素材升級。
- 階段性新主武器購買或武器分支；此項若加入，需另行定義足以形成明顯擊殺門檻變化的完整武器階段，不重新加入小幅傷害等級。

## 2. 共通等級與購買規則

- 每個升級使用穩定 id 與非負整數等級保存；存檔不保存衍生後的毫秒數或實際槽位數。
- 等級 `0` 代表尚未購買。購買只能使指定升級增加一級，不可跳級、降級或超過 config 定義的最大等級。
- 每一級價格皆由 config 依目前等級查表；金幣不足、前置條件不符或已達最高級時，交易不改變金幣與升級狀態。
- 扣除金幣與提高等級必須產生同一份新進度並以一次一致寫入保存。保存失敗時，不得顯示已購買或只扣除金幣。
- UI 至少顯示目前效果、下一級效果、價格與是否已達最高級；不得要求玩家進入多層選單才能開始下一局。

## 3. 固定主武器基準

- 初版主武器基礎攻擊力固定讀取 `combatConfig.initialWeaponDamage`，目前為 `10`；它不是永久升級等級，也沒有購買入口。
- 每局開始時直接以固定主武器基準建立單局快照，不從存檔解析主武器攻擊力等級。
- 手動攻擊與已解鎖的懸停自動攻擊使用同一份固定基準；已裝備 Sword 的固定加成再加到該數值上，Ring 觸發時仍快照該次命中的最終武器傷害。
- 效果卡以各自 config 定義的初始武器倍率推導傷害，不因 Sword、自動攻擊間隔或未來階段性武器內容自動放大。
- `combatConfig.minimumWeaponDamageIntervalPerTargetMs` 維持所有武器攻擊共用的准入限制，不是玩家可購買的攻速屬性。
- 永久升級 UI、購買 service、正式 config 與新 schema 存檔都不得保留 `weaponDamage` 升級節點；舊存檔移除方式見[存檔系統規格](./save_system.md)。

## 4. 懸停自動攻擊

### 4.1 解鎖與間隔等級

這條成長線依序為：

1. 購買一次「解鎖懸停攻擊」。
2. 購買「自動攻擊間隔 I」。
3. 購買「自動攻擊間隔 II」。
4. 購買「自動攻擊間隔 III」。

- 解鎖狀態與間隔等級分開保存；解鎖前的間隔等級必須為 `0`，也不可購買間隔升級。
- 解鎖後、尚未購買間隔升級時使用間隔等級 `0` 的基礎間隔；之後依序套用等級 `1～3`。
- 永久升級 config 保存間隔等級 `0～3` 對應的毫秒數；所有值必須大於零，並隨等級提高而嚴格縮短。
- 間隔等級只改變自動攻擊嘗試頻率，不改變手動點擊的准入間隔、傷害或輸入方式。

目前解鎖後的間隔等級 `0～3` 依序為 `1,500 ms`、`1,200 ms`、`900 ms`、`600 ms`。

### 4.2 戰鬥邊界

- 游標停留在合法寶箱目標上時，自動攻擊依目前間隔嘗試造成主武器傷害；游標沒有合法目標時不得產生攻擊或預先累積額外次數。
- 自動攻擊與手動攻擊進入相同的每目標武器傷害准入、傷害、死亡、收益與 Jackpot 結算入口，不建立第二套戰鬥公式。
- 自動攻擊取得固定主武器基準與已裝備 Sword 加成。
- 自動攻擊不是有效手動武器命中，因此不增加 Ring 計數，也不觸發任何明確標示為手動限定的裝備效果。
- 自動攻擊必須降低連點負擔，但不得讓手動輸入失去明顯的加速價值；正式目標區間需寫入平衡 config，未建立前不得宣告平衡完成。
- 暫定平衡門檻為自動武器傷害占全部武器傷害不超過 `40%`，全部升級完成時手動武器傷害占比至少 `55%`。

## 5. 裝備槽里程碑

### 5.1 目前規則

- 基礎裝備槽數為 `equipmentConfig.initialSlotCount`，目前為 2 格。
- 「裝備槽 III」是裝備槽升級等級 `1` 的一次性里程碑，使下一局起的可用槽位增加 1 格，成為 3 格。
- 本里程碑沒有自動攻擊等級前置條件；只需支付該級價格。
- 購買只影響之後開始的單局，不在進行中的單局中途新增槽位或重新分配既有裝備。

### 5.2 未來擴充到 4 格

- 存檔只保存同一個「裝備槽升級等級」，不保存 `3` 或 `4` 等實際槽位數，也不為每一格建立不同布林欄位。
- 永久升級 config 以 `additionalSlotCountByLevel` 類型的等級表保存額外槽位數：目前等級 `0` 對應 `0`、等級 `1` 對應 `1`。
- 單局實際槽位數固定由「基礎槽位數 + 目前等級對應的額外槽位數」推導。
- 未來加入「裝備槽 IV」時，只需在同一升級線追加等級 `2` 對應的額外 2 格、價格與顯示資料；不新增存檔欄位、平行槽位系統或另一種購買流程。

## 6. 初始價格、節奏與介面

### 6.1 初始效果值與價格

| 效果線 | 等級 0 | 等級 I | 等級 II | 等級 III |
| --- | ---: | ---: | ---: | ---: |
| 懸停自動攻擊間隔 | 1,500 ms | 1,200 ms | 900 ms | 600 ms |

自動攻擊的等級 `0` 間隔只會在另行購買解鎖後生效；未解鎖時不執行自動攻擊。

| 升級 | 初始價格 |
| --- | ---: |
| 解鎖懸停攻擊 | 600 |
| 自動攻擊間隔 I | 900 |
| 自動攻擊間隔 II | 1,400 |
| 自動攻擊間隔 III | 1,800 |
| 裝備槽 III | 2,200 |

- 兩條線可自由選擇，不用表格順序強迫購買；玩家可以先解鎖懸停攻擊，也可以直接存錢購買第三槽。
- 第三槽是改變局內配置容量的一次性高影響里程碑，因此價格高於單級自動攻擊間隔成長。
- 移除主武器微幅升級後，所有購買局數、總收益增幅與最早可購買時點都必須重新模擬；舊版總價、首局購買攻擊力與優先攻擊力路線得到的結論全部失效，不得沿用。

### 6.2 config 權責

- `hoverAutoAttack.unlockCostGold` 保存 `600`。
- `hoverAutoAttack.intervalCostGoldByLevel` 依序保存等級 `1～3` 的 `900`、`1_400`、`1_800`。
- `hoverAutoAttack.intervalMsByLevel` 依序保存間隔等級 `0～3` 的 `1_500`、`1_200`、`900`、`600`。
- `equipmentSlots.costGoldByLevel` 目前只保存等級 `1` 的 `2_200`；未來裝備槽 IV 的價格追加在同一等級表。
- UI、購買 service、測試與模擬都讀取上述 config，不另寫價格；存檔不保存價格。價格不隨當局收入、解鎖階段或玩家餘額動態改變。

### 6.3 節奏與介面

- 價格應讓玩家看得見下一個目標正在接近，但不要求第一局後或每局都固定買到升級。
- 兩條線都應在結算後的同一層介面可見。購買成功後立即更新目前／下一級資訊，開始下一局的主要按鈕始終保持清楚。
- 不用隨機出現的商店、每日輪替或隱藏條件控制目前兩條升級，避免玩家有錢卻找不到預期升級。

## 7. 驗證要求

### 7.1 確定性核心測試

至少驗證：

- 目前兩條升級都只能依序購買；金幣不足、前置條件不符及最高級時不會扣款或改變等級。
- 各級購買價格直接讀取正式 config；測試不得複寫表格數字，並須確認所有目前開放等級都有唯一價格且都能被購買流程解析。
- 每次購買的金幣與等級變更原子一致；保存失敗、重新載入、匯出／匯入及重置後結果正確。
- 主武器傷害固定讀取 `combatConfig.initialWeaponDamage`，永久升級 definition、購買入口與新 schema 存檔都不存在 `weaponDamage`。
- 自動攻擊未解鎖時不執行；解鎖後使用間隔等級 `0`，間隔等級 `1～3` 依 config 嚴格縮短。
- 自動攻擊與手動攻擊共用武器傷害准入與結算；自動攻擊取得 Sword 加成但不增加 Ring 計數。
- 裝備槽升級等級 `0` 解析為基礎 2 格，等級 `1` 解析為 3 格；購買發生在局外時不改變正在進行中的單局快照。
- 對裝備槽等級表追加未來等級 `2` 時，同一解析函式能得到 4 格，不需新增特例或存檔欄位。

### 7.2 平衡模擬與人工檢查

- 實作任何攻擊力、間隔、價格或槽位數值前，必須依[初版核心平衡驗證閘門](./progression_and_validation.md#182-初版核心平衡驗證閘門)執行受影響的固定 seed 矩陣，並更新[當前核心平衡報告](./balance_report.md)。
- 平衡案例至少涵蓋全部等級 `0`、自動攻擊解鎖與各間隔等級、第三槽、全部目前升級完成，以及第三槽搭配不同裝備組合；不得保留主武器攻擊力等級案例。
- 需要觀察每局手動／自動有效命中與傷害占比、擊殺與收益、Jackpot 結果、第三槽啟用時間與額外輸出，以及各級所需局數分布。
- 模擬必須分別檢查優先自動攻擊、直存第三槽與買完全部升級的路線；不得沿用已移除的優先攻擊力路線或舊總價除以平均單局收益的靜態估算。
- 人工確認每一級自動攻擊間隔可感知、手動點擊仍值得使用，第三槽能帶來新的局內組合期待而不讓前兩格裝備選擇失去意義。
- 任一具名目標區間尚未建立或案例未通過時，該升級只能標記為待校準，不得宣告平衡完成。
