# 前端與遊戲執行架構

本文件定義初版的渲染、UI、狀態管理、遊戲迴圈、生成排列、動畫與 config 邊界。遊戲行為規則以 [spec.md](./spec.md) 為入口；階段武器商店細節見[階段武器商店規格](./weapon_shop.md)；永久升級細節見[永久升級規格](./permanent_upgrades.md)；效果卡細節見[效果卡規格](./effect_cards.md)；裝備細節見[裝備卡與局內裝備系統規格](./equipment_system.md)；存檔細節見[存檔系統規格](./save_system.md)。

## 1. 技術選擇

- 專案原始碼使用 TypeScript。
- 樣式使用 SCSS；CSS 視覺數值留在 SCSS 變數或對應元件樣式中。
- PixiJS v8 負責全螢幕 canvas 戰鬥場地。
- React 負責覆蓋在 canvas 上的 HUD、選單、結算、解鎖、武器商店、升級與存檔 UI。
- XState 負責離散且有先後限制的遊戲流程。
- Zustand 負責 React 與遊戲橋接所需的低頻記憶體資料。
- IndexedDB 由獨立存檔 service 管理，不由 Zustand 直接持久化。

這些工具不得保存彼此職責內的第二份真實資料。

## 2. 畫面分層

由下至上：

1. 全螢幕 PixiJS canvas。
2. React HUD 疊層。
3. React 結算、解鎖、確認或選單疊層。

### 2.1 PixiJS canvas

負責：

- 寶箱怪與 Jackpot。
- 場地移動、牆面反彈與逃跑。
- 點擊判定與武器命中。
- 效果卡與裝備的共用附著、點擊及各自結算。
- 裝備掉落、目的地保留、飛行、到達啟用與局內戰鬥效果。
- 受擊、掉落、噴獎、破碎及其他戰鬥動畫。
- 結算期間的動態裝飾背景。

### 2.2 React 與 SCSS

負責：

- 主倒數條。
- Jackpot 追逐倒數條。
- 金錢、通用裝備欄、可開啟的中央背包面板、排序控制、拖曳／點選換裝、裝備 tooltip 與其他 HUD。
- 戰鬥收益、裝備自動出售分組、本局總收益、解鎖、武器購買／切換、升級、匯入／匯出與重置 UI。
- 結算時覆蓋 canvas 的輕微高斯模糊。

HUD 的非互動區域應讓指標事件穿透到 canvas；按鈕、對話框與結算遮罩才攔截事件。進入結算時，除了 UI 遮罩攔截之外，遊戲流程本身也必須拒絕戰鬥輸入。

背包遮罩與結算遮罩是兩種不同呈現：背包只使用不帶 `filter`／`backdrop-filter` 的半透明背景攔截戰場輸入，不套用高斯模糊。背包面板、完整裝備欄、槽內實際卡圖、拖曳預覽及 tooltip 必須位於該遮罩上方並維持原清晰度；只有正式結算沿用輕微高斯模糊。

右上角金錢 HUD 顯示本局累計收益。它使用 React／SCSS 實作逐位數字滾輪，只接收顯示目標，不參與獎勵計算或入帳。

### 2.3 兩種倒數條

- 主倒數條在正式單局開始時啟動。
- Jackpot 偽裝在普通流中時，不顯示 Jackpot 倒數條。
- 玩家打破 Jackpot 外殼、正式進入追逐時，才顯示並啟動 Jackpot 倒數條。
- Jackpot 追逐結束、擊殺或逃脫後，Jackpot 倒數條消失。
- 倒數真實值由遊戲執行層持有；React 只取得足夠流暢的顯示快照，不驅動遊戲時間。

## 3. 狀態所有權

| 層級 | 保存內容 | 不保存內容 |
| --- | --- | --- |
| XState | 載入、待機、遊戲中、背包開關、Jackpot 追逐、單局收尾、結算存檔、結算揭示、解鎖提示等流程 | 每幀位置、速度與動畫進度 |
| Zustand | 已載入的局外進度、貨幣、武器持有／裝備狀態、升級、UI 所需結算結果與背包低頻快照 | XState 已持有的流程狀態、IndexedDB 寫入細節 |
| Pixi runtime | 場上實體、效果卡、局內裝備實例／槽位保留、成功掉落實例、座標、速度、血量、逐幀計時與動畫 | 永久進度、出售價格與存檔格式 |
| Save service | IndexedDB 讀寫、版本與匯入／匯出 | React UI 與 Pixi 顯示物件 |

### 3.1 XState 流程責任

至少需要表達下列離散流程：

```text
loadingSave
→ ready
→ playing
   ├─ gameplay: jackpotDisguised／jackpotWaitingToReturn／jackpotChasing／jackpotResolved
   └─ backpack: closed／open
→ finishingRound
→ savingSettlement
→ settlement
→ unlockAnnouncement（可選）
→ ready
```

- XState 只接收 `JACKPOT_REVEALED`、`JACKPOT_TIMER_EXPIRED`、`ROUND_TIMER_EXPIRED`、`JACKPOT_EXITED` 等離散事件。
- `OPEN_BACKPACK`／`CLOSE_BACKPACK` 只切換 `playing` 內的正交背包狀態並協調 runtime 暫停意圖，不得離開或重設目前 Jackpot 子狀態；離開 `playing` 前必須先關閉背包並取消未提交操作。
- 不得每幀向 XState 發送位置、速度或一般寶箱血量。
- 不得在 Zustand 再保存一份可與 machine 不一致的 `gamePhase`。

### 3.2 Zustand 責任

適合保存：

- 生涯完成局數。
- 已解鎖寶箱怪。
- 金幣、持有／裝備中的主武器與永久升級。
- 最近一局結果快照。
- React HUD 需要的低頻資料。
- 背包與裝備欄顯示所需的版本化低頻快照；它不是裝備效果或槽位分配的真相。

Zustand 是記憶體中的應用狀態，不是存檔系統。載入、武器購買／切換、購買升級、完成結算或確認解鎖後，由明確的協調流程呼叫 save service。

### 3.3 結算交易責任

- `finishingRound` 先禁止新的戰鬥結果，要求 Pixi runtime 以 reward instance 為單位凍結成功取得裝備；快照建立後才能取消飛行動畫、槽位保留、Ring 佇列及局內裝備狀態。
- 自動出售由不依賴 Pixi 或 React 的純資料 service 處理。它讀取出售快照與 `settlementConfig.equipmentSale`，依 equipment id 分組並產生數量、小計與出售總額；不同稀有度的不同 id 不得只因價格相同而合併。
- `RoundResult` 必須分開保存戰鬥收益、裝備出售收益、最終總收益、分組出售明細、擊破數與 Jackpot 結果；最終總收益是唯一寫入玩家金幣的數字。
- `savingSettlement` 將 `RoundResult`、生涯局數、新解鎖與待展示提示作為同一份一致進度寫入 IndexedDB。寫入成功才進入 `settlement`；失敗時停留在可重試的錯誤流程，不得先顯示已入帳結果。
- React 結算只播放已保存 `RoundResult` 的逐組揭示與總收益數字滾動。點擊快轉、動畫完成、卸載或重播都不能呼叫出售計算或再次寫入金幣。
- `settlement` 揭示完成後才可進入 `unlockAnnouncement`。沒有出售項目時直接略過出售列，不建立空的等待狀態。

### 3.4 局外成長交易與單局快照

- React 升級 UI 只送出要購買的穩定升級 id，不自行計算價格、下一級效果或扣款結果。
- 不依賴 React、Pixi 或 IndexedDB 的永久升級 service 依正式 config、目前等級與金幣驗證最高級、線性前置及價格，產生包含扣款與新等級的完整下一份進度。
- React 武器商店只送出穩定武器 id 與購買／裝備意圖；不依賴 React、Pixi 或 IndexedDB 的武器交易 service 依正式 config、持有狀態、前置武器與金幣驗證，產生包含扣款、持有集合與裝備武器的完整下一份進度。購買成功時同時裝備該武器。
- 協調流程以一次 save service 寫入保存該進度；成功後才更新 Zustand 與購買 UI。保存失敗時保留購買前狀態並顯示可重試錯誤，不得只扣金幣或只升等。
- 開始單局前，以已保存的裝備武器 id、永久等級與正式 config 建立不可變的單局成長快照，至少包含武器 id／基礎攻擊力、懸停自動攻擊是否解鎖與間隔，以及實際裝備槽數。
- Pixi runtime 只接收解析後的單局快照，不讀取 IndexedDB，也不逐幀查詢 Zustand。主武器手動／自動來源與裝備系統共用其中同一份武器資料，避免各自解析出不同數值。

## 4. PixiJS 遊戲迴圈

- 使用 PixiJS `Application` 自己的 ticker 驅動遊戲更新與渲染。
- 位移、倒數與動畫使用 ticker 的 `deltaMS`，不得把 `deltaTime` 當毫秒。
- 高頻更新直接作用於 Pixi runtime 與顯示物件，不經過 React render 或 Zustand action。
- 暫停、頁籤切換與大型幀落後不得造成單幀超大位移；時間邏輯需有明確上限或補償策略。
- 背包暫停由 runtime 在 ticker 的遊戲更新入口提早返回，不停止 `Application` ticker 或 renderer；所有遊戲系統及手動更新的 Pixi 動畫都停在同一 frame，恢復後不補算暫停時間。React 面板保持可操作。
- 遊戲更新與 React 的純 UI 動畫必須可分開啟停；代表遊戲進度的 HUD SCSS 動畫需跟隨 runtime 暫停狀態。

### 4.1 正式單局模式

- 啟用寶箱生成、共用外掛卡附著、效果卡與裝備結算、戰鬥輸入、血量、掉落、收益與統計。
- 使用開局前建立的成長快照初始化本局裝備武器、自動攻擊與裝備槽；主武器不從永久等級解析，本局進行中也不重新套用局外購買或切換。
- 玩家開始本局時，先同步完成普通寶箱開場預填，再讓主倒數進入 ticker 更新；第一個可操作 frame 已有可攻擊目標。
- 主倒數完整局長讀取 `roundConfig.durationMs`，初始值為 `30_000`；ticker、狀態機、React HUD 與平衡模擬不得另寫固定秒數。
- 擊破造成有效場內目標降至小於或等於 config 門檻 `6` 時，由可測試核心狀態執行延後確認並補向 `12` 個有效目標；Pixi 只顯示新實體，且只有確認時有效目標歸零才顯示清場回饋。Jackpot 追逐期間核心狀態不得執行補場。
- 主倒數與必要的 Jackpot 倒數正常運作。

### 4.2 裝飾背景模式

- ticker 與畫面渲染持續。
- 沿用同一生成器，但以裝飾參數生成乾淨寶箱。
- 停止戰鬥、效果卡、收益、掉落、正式計時與 Jackpot 邏輯。
- 裝飾實體不進入下一局，開始新局前統一清除。

### 4.3 實體移除生命週期

- PixiJS 實體一旦在某幀被移出 runtime 集合並呼叫 `destroy()`，該幀後續流程不得再讀寫它的 position、scale、rotation、事件或子物件。
- 逐幀視覺更新必須把 `container.destroyed` 視為正常的終止狀態並立即返回，不能讓已移除實體的 transform 存取例外中斷共用 ticker。
- 退場路徑必須涵蓋普通寶箱、Jackpot 偽裝流出、Jackpot 擊破及 Jackpot 向下逃離；任何一條路徑都不得因單一實體銷毀而停止主倒數或其他場景動畫。
- 修正此類生命週期 bug 時，必須新增「銷毀後同幀視覺更新不丟例外」的核心回歸測試。

## 5. 場地生成與排列

普通寶箱不使用固定或半固定軌道。

### 5.1 候選位置選擇

1. 唯一的候選位置選擇器接收連續矩形範圍，不區分成兩套排列演算法。
2. 後續上緣生成把候選最小 Y 與最大 Y 設為同一入口座標，只隨機抽選水平位置；開場填場與低密度續戰補場則同時在水平及垂直場內可生成範圍抽選候選位置。
3. 以即將生成卡牌的矩形範圍，與相關現有卡牌矩形計算重疊；兩種場內填場都必須比較場上全部既有實體，包括仍在上方入口等待帶的寶箱，不能沿用只檢查上緣附近實體的篩選。
4. 排除超過最大允許重疊比例的候選位置，再從剩餘候選中選擇重疊最少者。
5. 開場填場重複建立普通寶箱，直到單次候選選擇無結果或達到既有全場同時存在上限；續戰補場沿用同一迭代器，但在有效目標達到 `clearRefill.targetEffectiveCount` 時停止。兩者都不得為了填滿而放寬重疊限制。
6. 後續上緣生成若全部候選不合格，才依既有重試間隔延後；開場填場失敗則直接完成並開始本局，續戰補場失敗則保留既有上緣實體與正常生成排程，不強塞或建立補場專用寶箱。

### 5.2 排列原則

- X 座標不得量化成數條固定線。
- 允許少量重疊以保留自然散落感，但需維持主要點擊區可辨識。
- 場內填場 Y 座標不得量化成固定橫列；卡牌必須完整位於畫面頂端以下，且卡牌底緣不得進入 config 指定的場內填場底部不可生成區。
- 卡牌尺寸、場地寬高與裝置比例變化時，候選範圍與重疊計算使用實際顯示矩形；若可生成高度不足一張卡，合法結果是沒有場內填場實體，後續上緣生成仍照常運作。
- 開場與續戰補場寶箱都沿用完整正式生成內容與向下速度；Jackpot 不加入場內填場，而是在主倒數第 `6` 秒或既有重返時點從上緣嘗試生成。
- 普通卡牌維持由上往下的主要動勢，不以左右蛇行製造散落感。
- Jackpot 真身不受普通排列限制，且渲染層級固定高於普通寶箱。

### 5.3 可調 config

- 水平安全邊距。
- `spawnConfig.fieldFillBottomNoSpawnHeightPixels`：開場填場與續戰補場共用的底部不可生成高度。
- 最大允許重疊比例。
- 候選位置數量。
- 全場同時存在上限；開場填場沿用此上限，續戰補場另受有效目標數 `12` 限制，但不複製另一份全場容量。
- 低密度觸發上限、補場目標有效數、確認等待、最低剩餘時間與有效顯示比例。
- 找不到位置時的重試間隔。
- 生成間隔與各寶箱怪生成權重。
- `roundConfig.initialJackpotSpawnDelayMs`：Jackpot 首次上緣生成延遲，初始值為 `6_000`；換皮重返使用原本獨立 config。

### 5.4 低密度、清場與續戰狀態邊界

- 有效目標計數、低密度／清場判定、確認等待、最低剩餘時間、Jackpot 追逐排除、補場許可與重新允許條件必須是可測試核心狀態，不得由 Pixi 場上 child 數量、動畫完成 callback 或 React HUD 推導。
- 有效場內目標使用 runtime 戰鬥資格與卡牌顯示矩形／場地交集比例的純資料結果；破碎、金幣、裝備及效果 Sprite 不進入判定。
- 每次死亡結算完成後才允許在有效目標 `≤ 6` 時提出補場確認，普通流出只移除實體、不主動提出確認；確認時有效目標為 `0` 才另外送出清場回饋。
- 唯一場內填場服務接收目前普通生成池與全部占用矩形，同時供開場及續戰補場使用；不得保留一個只改名稱的清場專用生成器。
- 同一場內填場服務只接受呼叫端提供的純顯示模式：開場預填立即顯示，續戰補場則只替該次新建立實體啟動縮放入場。不得為了演出複製生成、排列、內容附著或實體建立流程，上緣生成與補場前既有實體也不得被補套動畫。
- 續戰補場不得重設普通生成與 Jackpot 排程；Jackpot 已到嘗試時點時先執行既有上緣生成，再使用剩餘容量把有效目標補向 `12`。Jackpot 追逐開始時取消待確認補場，追逐期間不建立新補場。
- 補場成立後，runtime 保存「同一段無新手動介入的持續連鎖已使用補場」狀態；效果系統仍完成既有前搖、飛行、持續傷害與後續觸發，只把再次補場的請求拒絕。
- 有效手動武器傷害或該連鎖全部結束後可重新允許未來補場；重新允許不得追溯補發關閉期間的低密度或空場。
- 回合收尾與場景清理必須取消待確認補場並重置低密度／清場狀態，裝飾模式不建立正式補場。

## 6. Jackpot 追逐運動

### 6.1 追逐

- 兩次碰牆之間維持直線速度，路徑應可預讀。
- 碰牆時依牆面法線反射速度向量，使入射與反射方向合理。
- 只允許小幅且有上限的角度修正，用來避免完全水平、垂直或永久重複路徑。
- 卡牌旋轉只呈現微幅傾斜，不能連續翻滾。
- 旋轉應快速跟隨動勢並自然回正，不拖延追逐操作。

### 6.2 Jackpot 倒數先耗盡

1. 立即停止 Jackpot 受擊。
2. 保留當下世界座標，播放不產生淨位移的短促抖動僵直。
3. 鎖定當下 X 座標，忽略側牆碰撞，向下直線逃離。
4. Jackpot 倒數條消失。
5. 主倒數、普通生成與其他寶箱戰鬥繼續。

### 6.3 主倒數先耗盡

1. 立即停止所有戰鬥輸入、生成、收益與正式計時，並取消尚在效果卡前搖中的待發動攻擊。
2. 若 Jackpot 正在追逐，播放相同的抖動僵直與向下逃跑。
3. Jackpot 離場後移除 Jackpot 倒數條並完成本局。
4. 若 Jackpot 已被擊殺或已逃脫，不等待不存在的 Jackpot 動畫。
5. 進入 React 結算遮罩與 Pixi 裝飾背景模式。

## 7. 動畫系統

動畫原則是「預備短、命中清楚、收尾快」。純視覺動畫不得延後傷害、死亡、獎勵或流程狀態生效。

可戰鬥 Mimic 的場景節點分成外層實體 Container 與內層視覺 Container。外層保存邏輯座標、完整 hit area、事件與既有受擊 transform；內層統一包含寶箱 Sprite、裂紋、閃白及外掛卡，只承擔不影響戰鬥資格的視覺 transform。續戰補場從零尺寸放大、微幅超過原始尺寸後回正時只縮放內層視覺，因此完整點擊範圍、向下移動、效果卡命中與傷害結算都從實體建立時立即生效。

補場縮放狀態使用既有 Pixi ticker 的 `deltaMS` 推進並在完成後停止更新，不建立另一個計時器或 tween 系統；實體在演出中被擊破、移除或場景清理時，動畫隨既有實體生命週期立即終止。整批補場同時開始，不加入逐隻延遲、位移或淡入。

補場寶箱在縮放途中被擊破時，效果卡與可見裝備卡脫離 Mimic 視覺樹後必須保留當下世界位置與旋轉，並恢復獨立卡片的基準尺寸；不得把接近零或放大峰值的補場入場倍率帶入效果卡前搖、裝備拋射或後續收集動畫。

效果卡噴出前搖是明確的戰鬥時序，不屬於可任意中斷而不影響結果的純視覺動畫。落雷與隕石都必須等前搖完成才發動；主倒數在前搖期間耗盡則取消待發動攻擊。已發射但尚未落地的隕石仍未結算傷害，也必須在主倒數耗盡時取消。

裝備從掉落到抵達槽位也是戰鬥時序：目的地在噴出前完成保留，但能力只在抵達槽位時啟用。純視覺更新不得提前或重複觸發啟用。

### 7.1 受擊

- 閃白。
- 以原位置為中心的短促卡牌抖動。
- 微幅後仰、橫向偏移或向上彈動。
- 動畫完成後回到正確邏輯座標，不累積視覺偏移。

#### 7.1.1 每目標武器傷害間隔

- 每個可戰鬥 `RuntimeMimicEntity` 保存 `nextWeaponDamageAllowedAtMs`，初始值允許第一擊立即生效。准入判定使用 runtime 的遊戲經過時間，不使用 `Date.now()`、計時器或真實牆鐘時間。
- 手動點擊與懸停自動攻擊在進入既有共用傷害入口前，先比較當前遊戲時間與該實體的下一次允許時間；成功造成武器傷害後才依 `combatConfig.minimumWeaponDamageIntervalPerTargetMs` 推進下一次允許時間。
- 間隔內的攻擊必須回傳未套用傷害，不更新血量、裂紋或任何受擊動畫，也不建立武器 hit 特效。剛好到達下一次允許時間時視為有效，且不同實體的時間互不影響。
- 落雷、隕石與其他效果卡直接進入既有共用傷害／死亡／收益／Jackpot 結算，不讀取或更新武器傷害間隔。間隔只是傷害來源准入規則，不得複製另一套傷害結算。
- Jackpot 偽裝外殼與揭露後真身沿用同一個 runtime 實體及 `nextWeaponDamageAllowedAtMs`；揭露時重設 texture、血量、裂紋與移動資料，但不得重設剩餘武器傷害間隔。實體死亡或離場後隨實體一併清除，不建立全域冷卻表。
- 確定性核心測試必須涵蓋第一擊、間隔內拒絕、剛好到達邊界、不同實體互不影響、效果卡繞過限制，以及 Jackpot 揭露後延續剩餘間隔；測試時間由參數注入，不依賴真實時間。
- 戰鬥與批次平衡模擬必須套用相同的每目標武器准入規則，不得繼續把原始點擊預算全部視為有效傷害；本規則或 config 數值改變時更新平衡版本並重跑完整矩陣。

#### 7.1.2 共用武器命中特效

- 可受擊實體的 pointer tap 必須把實際 canvas／世界點擊座標傳入手動攻擊入口；有效手動攻擊在該座標置中建立原色 `effects/hit.png`。同一座標同時作為該次命中若觸發 Ring 批次時的不可變視覺原點。
- pointer enter 與同一實體內的 pointer move 必須把最新世界游標座標交給懸停自動攻擊狀態；move 只更新座標、不重設既有倒數，pointer leave、實體失效或回合清理則同時清除目標與座標。有效自動攻擊快照該次最新座標，再依 config 向左下偏移並套用專用 tint。
- Ring 每段視覺固定使用觸發批次的手動點擊座標，再依 config 向右上偏移並套用 Ring tint；後續游標與目標移動都不改寫這個視覺原點。Ring 仍依 runtime identity 判斷傷害資格，視覺位置不參與命中。
- 武器 hit 是純視覺回饋，不參與傷害、點擊範圍、裂紋或死亡判定。手動與自動攻擊只有在共用傷害入口確認成功後才建立；被武器間隔拒絕的攻擊，以及落雷、隕石等效果卡傷害都不建立。
- `effects/hit.png` 是 `1750 × 218` 水平圖帶，切成 5 張 `350 × 218` frame；全部來源共用同一組 frame texture、AnimatedSprite 播放器、中心 anchor、`weaponHitEffect.displayScale` 與 `weaponHitEffect.animationDurationMs`，不得為手動、自動或 Ring 複製播放器。切幀尺寸不得隨顯示比例改動。
- 特效建立在獨立的世界特效層，不掛在 Mimic Container 下，因此致死攻擊移除 Mimic 後仍能完成播放；特效 `eventMode` 為 `none`，不得攔截後續輸入。
- 圖帶結構、顯示尺寸與總播放時間由 `animationConfig.weaponHitEffect` 管理；自動與 Ring 各自的偏移及 CSS tint 分別由對應功能 config 管理，只在建立 Sprite 時轉換顏色。游標座標及逐幀狀態只存在 Pixi runtime，不進入 XState、Zustand 或存檔。

#### 7.1.3 階段式裂紋

- 裂紋由 Pixi runtime 持有，只是顯示狀態，不進入 XState、Zustand、存檔或戰鬥結算資料。
- 可受擊實體必須同時保留目前血量與目前外觀的最大血量，以純函式依血量比例判定 `intact`、`subtle`、`severe` 三種顯示階段。
- 卡牌顯示順序固定為 Mimic 底圖、裂紋層、受擊閃白層、外掛卡扇形層；裂紋與外掛卡都跟隨 Mimic 父層的座標、縮放、抖動及 Jackpot 微幅旋轉。效果卡與後續裝備卡共用外掛卡扇形層，不各自建立重疊的排列容器。
- 裂紋使用 PixiJS v8 `Graphics`／`GraphicsContext` 建立程序式線條，不新增每種 Mimic 專用裂紋圖片。
- 準備三組固定裂紋圖樣；同一圖樣的輕微與明顯階段共用主裂紋路徑，明顯階段只延伸分支與邊緣效果，不重新抽取裂紋位置。
- 穩定的裂紋幾何應共用 `GraphicsContext`，實體只切換對應階段的 context 或可見狀態，不可在 ticker 中反覆 `clear()` 並重畫。銷毀個別實體時不得連帶銷毀其他卡牌共用的 context。
- 裂紋階段只在生成、受擊後血量改變及外觀身分切換時更新，不進入每幀血量判定。
- 明顯裂縫使用主裂縫兩側的明暗邊緣及最多 `2 px` 的局部視覺錯位營造深度；卡牌本體仍是一個完整實體，不在死亡前拆成多個可自由移動的部分。
- Jackpot 偽裝外殼被擊破時，先切換真身 texture、最大血量與目前血量，再把裂紋階段重置為 `intact`。後續受擊依 Jackpot 真身最大血量重新判定。
- 裝飾寶箱沒有戰鬥血量，不建立或不顯示裂紋層。
- 致死攻擊仍立即建立既有死亡破碎效果、移除場上實體並結算獎勵；裂紋顯示不得插入等待狀態。

### 7.2 噴獎

- 寶箱頭頂不顯示 `+收益` 文字，也不以無具體形狀的圓形粒子代替金幣。
- 每次擊破建立一批有上限的金幣 Sprite；視覺金幣數量依收益強度映射，不影響實際獎勵計算。
- 普通寶箱與 Jackpot 共用同一套金幣生命週期，Jackpot 只提高視覺數量與強度，不建立另一套更新流程。
- 金幣使用 `airborne`、`resting`、`collecting`、`completed` 等明確階段表達拋射、反彈、停留與收集，不套用只能單段移動後淡出的通用粒子模型。
- `airborne` 階段以 `deltaMS` 更新速度與重力，碰到每顆金幣自己的局部落地高度時修正穿透、反射垂直速度，並在完成隨機 2～3 次反彈後進入 `resting`。
- `resting` 階段固定顯示翻轉圖的最後一幀；短暫停留完成後切換 idle texture。
- `collecting` 階段以有明確終點的短促弧線飛向 React 金錢 HUD 提供的 canvas 目標座標，並在結束後回收或銷毀顯示物件。

#### 7.2.1 水平精靈圖帶共用讀取器

- 專案只保留一套水平精靈圖帶切幀工具；金幣、點擊、落雷、隕石、爆炸與龍捲風素材都必須沿用，不得再建立效果專用切幀流程。
- 共用工具接收素材識別、來源寬高、單幀寬高與幀數，驗證後由左至右建立 frame texture。
- `coin/gold_coin_flip` 是 `721 × 103` 的水平圖帶，切成 7 張 `103 × 103` frame texture。
- `effects/thunder` 是 `792 × 256` 的水平圖帶，切成 9 張 `88 × 256` frame texture。
- `effects/hit` 是 `1750 × 218` 的水平圖帶，切成 5 張 `350 × 218` frame texture。
- `effects/meteorite` 是 `1410 × 500` 的水平圖帶，切成 6 張 `235 × 500` frame texture。
- `effects/explode` 是 `1536 × 240` 的水平圖帶，切成 6 張 `256 × 240` frame texture。
- `effects/tornado_start` 與 `effects/tornado_end` 各是 `600 × 265` 的水平圖帶，分別切成 5 張 `120 × 265` frame texture；`effects/tornado_run` 是 `360 × 265`，切成 3 張相同尺寸的 frame texture。
- 讀取器只載入一次各素材的原始 texture source，同類顯示物件共享切出的 frame texture，不為每個顯示實體重複載入或複製圖片。
- 讀取器必須驗證來源尺寸、幀尺寸、幀數及總寬是否一致；不符合預期時拋出包含素材路徑、預期尺寸及實際尺寸的錯誤。
- `coin/gold_coin_idle` 是獨立的 `103 × 103` texture，在收集階段開始時切換使用。
- 清除個別 Sprite 或 AnimatedSprite 時不得連帶銷毀其他物件共享的 frame texture 或 texture source。

#### 7.2.2 Pixi 與 React HUD 橋接

- React 金錢 HUD、每個裝備槽及背包 icon 在掛載與尺寸／位置改變時，透過同一座標橋接提供具名 viewport 目標矩形；Pixi runtime 依 canvas host 的實際矩形換算成本地座標，不為裝備另建第二套 DOM 座標系統。
- 金幣逐幀座標、幀索引、反彈次數與動畫階段只存在 Pixi runtime，不進入 XState 或 Zustand。
- 邏輯 `roundGold` 在擊殺成立時立即增加；另以明確命名的顯示用本局收益保存數字滾輪目前可追逐的目標，兩者不得互相取代。
- 同一批金幣第一次抵達 HUD 時只發送一次低頻顯示事件，將該批 reward 加入顯示目標；不得逐幀或每顆金幣更新 Zustand。
- 多批金幣抵達順序不同時，顯示目標仍只能累加前進；React 數字滾輪在新目標到達時平滑重定向，最後必須停在正確整數。
- 數字滾輪卸載、動畫中斷或回合收尾都不影響 `RoundResult` 與存檔收益。

### 7.3 死亡破碎

- 優先將現有 Mimic texture 切成多個區塊。
- 各區塊可獨立飛散、旋轉、受重力影響並快速淡出。
- 切片行列、初速、散射、重力、旋轉與淡出時間由 config 管理。
- 破碎效果可被場景清理或流程切換中斷，不保留失效物件。

### 7.4 效果卡、落雷、隕石與龍捲風

#### 7.4.1 外掛卡組裝與附著

- 卡框 `effects/card_frame/normal`、效果卡 icon 與裝備素材都是 `264 × 328`；每張效果卡或裝備卡都使用一個卡框 Sprite 與對應內容 Sprite，以相同 anchor、位置及顯示尺寸疊在共用外掛卡 Container 內。裝備素材不得跳過卡框獨立顯示。
- 卡框與 icon 初始共同顯示為 `33 × 41`；右上偏移依縮放後的卡片尺寸重新配置，使突出比例維持一致，點擊矩形也使用縮放後尺寸。
- Runtime Mimic 持有單一外掛卡集合，不再以效果卡專用欄位表達；效果卡與裝備卡都由同一個右上角扇形 Container 排列，但各卡仍保留類別、內容 id、素材 id、稀有度與各自結算狀態。
- 同一 Mimic 的完整內容識別 `kind:id` 必須唯一；任何內容都不得重複生成來填滿較高卡片容量。
- 普通寶箱與 Jackpot 偽裝外殼先讓效果卡與裝備各自依 config 建立候選，再由共用純資料選卡模組公平、無重複裁切到容量上限，不以 definitions 陣列或類別順序固定偏向其中一種卡。
- Jackpot 真身沿用同一個純資料選卡模組，但使用保證選取策略：不執行普通候選機率，先以 `attachedCardConfig.capacity.jackpot.countSelectionChances` 決定 `minimum` 或 `maximum` 目標，再從當下可用內容池公平無重複抽選。兩個機率必須形成完整分布；不得另建一套平行的 Jackpot 卡片資料或排列系統。
- Jackpot 真身的可用內容池同時包含效果卡與裝備卡；可用唯一卡數少於目標時回傳全部內容，內容池大於目標時才裁切，且相同 seed 與內容池必須產生相同結果。
- 純資料排列函式依卡片總數與索引產生固定座標、角度及繪製順序。單張使用固定位置；多張形成撲克扇形，卡組整體微幅順時針旋轉，不讀取亂數。
- 外掛卡扇形位於 Mimic 右上角並跟隨 Mimic 移動與受擊動勢；卡片中心間距必須讓每張 icon 保留可辨識區域，後方卡先繪製、前方卡後繪製。
- 卡框與內容 Sprite 使用 nearest-neighbor 取樣並盡量對齊整數座標；卡面本身不得套用 Blur 或 Glow filter，稀有度光暈只存在分離的後方光暈層。
- 扇形 Container 內先放所有光暈，再放所有卡面，避免任何卡片的光暈覆蓋其他 icon；光暈與卡面可使用分離的子層，但必須由同一份排列結果同步 transform。
- 外掛卡正式稀有度由單一共用型別表達為 `N`、`R`、`SR`、`SSR`、`UR`；效果卡與裝備 definition 都引用該型別。`normal` 只保留為目前卡框素材 id，不再兼任稀有度。`N` 卡建立空光暈 Container 或直接略過光暈節點，不得建立 Graphics 或 Filter。
- `R`、`SR`、`SSR`、`UR` 全部走唯一的卡框形光暈建立器。清晰描邊與位於其後的模糊層從同一條精確貼齊 card frame 寬高與圓角邊界的路徑建立，不得為任一層預先放大或 offset 圓角矩形；描邊寬度與 Pixi `BlurFilter` 讓柔光自然向外延伸，並保留 padding 避免裁切。建立器只接收 rarity，不接收 effect／equipment id。
- `R` 使用藍色、`SR` 使用紫色、`SSR` 使用橘金色；`UR` 使用 local texture space 中由左上到右下的固定線性 `FillGradient`，五個 config 色碼依序為 `#AAFF01`、`#FF8F01`、`#FF00AA`、`#AA00FF`、`#00AAFF`。UR 清晰描邊與模糊層共用同一組漸層節點，不更新 gradient transform，因此色帶不流動。
- 每個會發光的稀有度各自重用穩定的清晰描邊 `GraphicsContext`、模糊層 `GraphicsContext` 與 `BlurFilter`；同稀有度效果卡與裝備卡共享，ticker 只更新個別卡片光暈 Container 的 alpha。不得每幀建立 filter、`clear()` 重畫、重算幾何，或保留 Ring、龍捲風、隕石等依內容命名的光暈資源。
- Mimic 本體維持既有點擊矩形；外掛卡突出部分逐張以自身旋轉矩形判定，所有矩形與 Mimic 本體形成聯集並導向同一攻擊事件，不建立涵蓋大片空白的外接點擊區，重疊區也只送出一次攻擊。
- 各箱種與 Jackpot 偽裝沿用 `attachedCardConfig` 的共用容量；Jackpot 真身目標張數與選取權重讀取 `attachedCardConfig.capacity.jackpot`，可用種類不足時全部插上，不得用重複內容補滿。

#### 7.4.2 前搖與重新掛層

- 攜帶者死亡或 Jackpot 偽裝外殼被打破時，先取得尚未結算的全部外掛卡；效果卡必須在 Mimic 被銷毀或換皮前逐張重新掛到世界特效層，保留扇形中的當下世界 transform。
- 同一寶箱的所有效果卡在同一事件中一起開始各自的前搖，不依卡片排列順序串行。效果卡在世界特效層以 config 驅動噴出、旋轉與淡出；共通初始前搖總時間為 `160 ms`。
- 每張效果卡前搖完成後移除自己的顯示物件，再依 effect id 以完整、可窮舉的分派進入落雷、隕石或龍捲風流程；不得以「非落雷一律視為隕石」等隱含 `else` 代替種類分派。共通前搖系統不得持有任一效果專用的活動攻擊狀態。
- 效果卡與裝備卡共存時，效果前搖與裝備掉落／收集流程可以並行。可見裝備依裝備 config 各自判定是否掉落，不因和效果卡共用扇形而保證取得。
- Jackpot 偽裝外殼被打破時可以不建立金幣獎勵，但外殼上的效果卡與裝備卡仍必須完整結算；換成真身前不得因 Container 銷毀而遺失插卡狀態。
- 偽裝外殼的外掛卡完成上述結算後不得轉移到真身；揭露流程依 Jackpot 自己的 config 與當下內容池建立新的外掛卡集合。擊破真身時，該集合再依一般效果觸發與裝備死亡掉落入口結算，並可與 Jackpot 金幣噴獎並行。
- 主倒數在前搖期間耗盡時清除待發動卡片，不呼叫效果傷害或連鎖；已發射但尚未落地的隕石與所有階段的龍捲風也一併清除。
- 場景清理必須同時清除附著中、噴出中與已發動的效果卡顯示物件，不得存取已銷毀 Container。

#### 7.4.3 落雷攻擊與動畫

- 落雷發動時以可注入亂數從當下有效實體選擇目標，位置取發動瞬間座標，不持續追蹤。
- 落雷 AnimatedSprite 使用底部中央 anchor，目標座標代表底端命中點，`88 × 256` 雷柱從該點向上顯示。
- 傷害判定使用以底端命中點為中心的 `88 × 88` 純資料正方形，不以整條 Sprite bounds 或透明像素作為戰鬥真相；邊長由 frame 寬度推導。
- 手動攻擊與落雷必須共用同一個傷害、死亡、收益與 Jackpot 結算入口；傷害來源只用來區分武器間隔與觸發規則，不複製結算流程。落雷不讀取或更新武器傷害間隔。
- 每道落雷建立前先決定該次命中實體集合，每個實體只處理一次，避免九幀動畫重複扣血。
- 落雷動畫使用 9 張共用 frame texture 的非循環 AnimatedSprite，初始總時間為 `450 ms`；各幀時間由總時間與幀數推導。
- 傷害在 AnimatedSprite 開始播放時立即生效，播放完成後只移除顯示物件，不再改變戰鬥結果。
- 任一效果卡造成的效果卡擊破以待發動佇列建立下一段 `160 ms` 前搖，不在目前傷害迭代或同步呼叫堆疊中遞迴觸發。

#### 7.4.4 隕石攻擊與動畫

- 令 `V = explosionFrameWidth × meteorite.displayScale`、`D = V × meteorite.damageAreaWidthMultiplier`；所有落點限制必須確保底部對齊的 `D × D` 傷害正方形完整位於目前 canvas 內。
- 第一顆發射前以可注入亂數從當下有效實體選擇目標，再求出能讓 `D × D` 命中區與該目標戰鬥矩形重疊的合法落點。若沒有目標，以 ticker `deltaMS` 最多等待 `meteorite.maximumFirstTargetWaitMs`；等待中出現目標就立即發射，等待耗盡且回合仍有效時改選隨機合法落點，不得因無目標取消。
- 第二顆起使用有限、可注入亂數的合法候選集合，優先選擇與同一卡所有先前落點至少相距 `D × meteorite.minimumLandingDistanceMultiplier` 的候選；沒有候選達標時選擇其「到既有落點的最小距離」最大者。候選數讀取 `meteorite.landingCandidateCount`，不得無限重抽或把其他卡的落點混入集合。
- 軌跡計算使用純資料函式：隕石順時針旋轉 `45°` 後，以 local 正 Y 對應的世界方向作為右上到左下飛行向量；再使用乘上 `meteorite.displayScale` 後的 frame 寬高計算旋轉 bounds，沿反向射線求出整個顯示範圍位於畫面外的起點。
- 起點、落點、單位方向、剩餘距離與發射時間是戰鬥時序資料；ticker 以 `deltaMS` 和 `meteorite.flightSpeedPixelsPerSecond` 更新距離，最後一步必須 clamp 到落點，不得穿越後再回拉。
- 隕石使用 6 張 `235 × 500` frame、底部中央 anchor 與 `meteorite.animationCycleDurationMs` 控制的循環動畫；實際顯示寬高為 frame 寬高乘上 `meteorite.displayScale`。移動與 frame 循環讀取同一 ticker，但顯示比例、位移速度與動畫速度三者互不取代。
- 每卡建立的隕石數量讀取 `meteorite.initialMeteoriteCount`。第一顆有目標時立即發射，無目標時依上限等待；後續每顆從上一顆實際發射時開始累加由 `meteorite.minimumLaunchIntervalMs` 與 `meteorite.maximumLaunchIntervalMs` 產生的可重複亂數間隔，不得在第一顆等待期間搶先發射。各顆飛行距離可以不同。
- 抵達時先取得當下仍有效的實體集合，以與爆炸底部共同對齊的 `D × D` 正方形計算命中，再透過既有共用傷害入口逐一結算四倍初始武器傷害。`D` 必須由爆炸實際顯示寬度乘上 `damageAreaWidthMultiplier` 推導；每顆對同一實體最多一次，不依爆炸幀重複結算。
- 抵達同一刻銷毀隕石 Sprite 並建立 6 張 `256 × 240` frame、底部中央 anchor、由 `meteorite.explosionAnimationDurationMs` 控制的非循環爆炸動畫；顯示寬高同樣乘上 `meteorite.displayScale`。隕石飛行前端、爆炸底部與傷害區底線使用完全相同的落點座標，不因縮放新增 position offset。
- 主倒數耗盡時，尚未發射或仍在飛行的隕石不得落地或造成傷害；已完成傷害的爆炸可以由場景清理統一中斷，不影響既有結果。
- `EffectCardSystem` 只擁有共通前搖與類型分派；落雷與隕石各自的活動狀態放在對應模組。手動攻擊與所有效果卡必須共用同一個傷害／死亡／收益／Jackpot 結算入口，不複製戰鬥結算。

#### 7.4.5 龍捲風生命週期、移動與傷害

- 龍捲風活動狀態由獨立效果模組管理；每個實例保存 `start`、`run`、`end` 階段、階段經過時間、位置、方向、速度、下一次轉向時間，以及每個 runtime 目標的傷害間隔。`EffectCardSystem` 與 `PixiGameRuntime` 只協調建立、更新、共用傷害 callback 與清理。
- 三段圖帶共用第 7.2.1 節的水平切幀器與手動 frame 更新器。`start`、`end` 單次播放，`run` 循環；不得開啟 AnimatedSprite 自動 ticker。一次 `deltaMS` 跨階段時，剩餘時間繼續推進下一階段，避免掉幀延長效果。
- 被擊破攜帶者位置是底部中央 anchor。單顆以可注入亂數選初始方向；多顆以隨機基準角度、圓周等分與受限擾動產生明顯不同方向。`start` 直行，`run` 依 config 間隔與限角隨機轉向，`end` 延續最後方向且不再抽新轉向；三段碰到場地邊界都使用同一反射與位置修正。
- 運動以 ticker `deltaMS` 與每秒速度推進，不使用 `setTimeout` 或牆鐘。所有亂數經依賴注入；固定 seed 與固定更新序列必須重現路徑、轉向排程及多顆方向。
- 只有 `run` 執行純資料傷害矩形碰撞：寬度 `120 × displayScale`，高度 `265 × displayScale × damageAreaHeightRatio`，由底部中央 anchor 向上延伸。戰鬥判定不得依賴 Pixi `getBounds()`、Sprite 透明像素或濾鏡後 bounds。
- 第一次有效重疊立即造成傷害；後續由每個「龍捲風實例 × runtime 目標」獨立間隔限制。離開再進入不提早重置；Jackpot 偽裝切換真身時清除該 runtime 實體在所有龍捲風中的間隔，讓下一次更新可以立即命中。
- `start`、`end` 與主倒數結束後都不能造成傷害。主倒數耗盡時立即取消待建立及場上龍捲風，不播放 `end`；正常 `run` 結束才播放移動中的 `end` 並在完成後銷毀顯示物件與實例狀態。

### 7.5 裝備掉落、收集與能力

- 裝備 definition、外部可見掉落判定、內部隱藏裝備抽選、批次目的地分配、槽位生命週期、Sword 加成、Ring 計數與追加攻擊都放在獨立的裝備 service/runtime 模組；`PixiGameRuntime` 只負責協調共用生成、傷害、死亡與場景生命週期，不繼續承擔裝備細節。
- 外掛候選先合併效果卡與裝備卡，再呼叫唯一的容量裁切模組。內部隱藏裝備是另一個最多一件的資料欄位，不占可見容量；兩條來源不得在生成器中互相覆寫。
- 死亡／破殼入口先凍結裝備快照。每張可見裝備用可注入亂數依 config 判定，隱藏裝備若存在則直接加入成功批次；同一裝備 instance 以結算狀態防止重複處理。
- 成功批次先由核心邏輯原子保留空槽，再建立動畫。槽位使用 `empty`、`reserved`、`equipped`；裝備獎勵使用 `airborne`、`resting`、`collecting`、`equipped`／`stored`、`cancelled` 等明確狀態。動畫只推進既定狀態，不自行重新選目的地。
- 槽位核心只接收單局快照解析出的實際槽位數。基礎槽位與永久額外槽位由同一組槽位狀態、分配與 HUD 橋接處理，不為「裝備槽 III」或未來「裝備槽 IV」建立專用分支。
- 金幣與裝備共用可注入運動參數的純資料 burst／bounce step；共用核心負責速度、重力、落地穿透修正、反彈與停留轉換，金幣和裝備只提供各自 config 與顯示同步。不得在裝備模組複製 coin-named 的位移公式或另建行為相同的平行物理。
- 裝備與金幣可同時噴出，但裝備排程需依 config 晚於同事件金幣抵達；無金幣的 Jackpot 偽裝破殼使用明確 fallback。所有等待、飛行與 Ring 固定間隔都由 app ticker 的 `deltaMS` 推進，不使用 `setTimeout` 或牆鐘。
- 裝備卡 texture 由 Pixi `Assets` 載入並快取一次，共用 texture source、使用 nearest-neighbor 取樣；個別 Sprite 銷毀時不得連帶銷毀共享 texture。
- React 渲染通用槽框、`equipment/backpack.png`、中央背包卡片清單與 tooltip，並透過第 7.2.2 節橋接回報目的矩形。飛抵槽位的裝備 Sprite 留在不攔截輸入的 Pixi HUD 裝備層並持續對齊，讓附著、飛行與已裝備 Ring 共用同一套卡形光圈；飛抵背包的 Sprite 完成回收後，React 依同一裝備 definition 組合卡圖與名稱。
- 裝備核心以穩定 instance identity 保存取得序列與位置；槽位分配、換裝原子提交、抵達啟用、背包無效狀態與回合清理都是 runtime 的單局真相。只有實例完成收集、換裝成功或清理等離散變更才推送低頻快照給 Zustand／React，不逐幀同步。
- React 只送出來源 `instanceId` 與目的地意圖，不計算排序以外的狀態轉移或裝備效果。pointer 拖曳與先選後放共用同一核心 command；非法／保留目的地在提交前拒絕，已占用目的地則由同一次提交把舊卡送回背包。背包卡內所有 DOM 圖片停用原生 drag，自訂拖曳掌握單一 pointer；只有合法目的地上的正常 `pointerup` 能提交，`pointercancel` 與失去追蹤只清除預覽及選取狀態。
- Sword 在共用武器傷害計算入口疊加已裝備件數；效果卡原有傷害公式不因 Sword 被隱式放大。
- Ring 只在共用武器准入入口確認手動點擊已實際造成傷害後增加玩家全域計數。觸發時快照最終武器傷害、目標 runtime identity、該次實際游標點擊位置與 Ring 數量，建立不遞迴的序列佇列；目標仍可受擊時，各段繞過武器間隔但回到既有共用傷害／死亡／收益／Jackpot 入口。
- 每段 Ring hit 視覺都在該段的 ticker 結算時點，以批次保存的游標原點加上 config 右上偏移建立並套用 Ring 專用 tint；目標仍可受擊時才在同一時點送出對應傷害。置中手動 hit、左下自動 hit 與右上 Ring hit 共用 AnimatedSprite／frame texture 與播放器；來源顏色在 config 保存為 CSS `#RRGGBB` 字串，只在建立效果時透過 Pixi `Color` 轉成 tint number，避免 filter／mask 額外 pass 及每幀顏色轉換。目標死亡、離場或不可受擊後，剩餘 Ring 段數仍沿用原游標快照依固定節奏產生視覺，不造成傷害或任何結算，也不得轉移目標或改用目前游標。Jackpot 偽裝切換真身因沿用 runtime identity，待結算段數仍可命中真身。
- 主倒數耗盡或場景切換時，統一取消飛行中裝備、槽位保留與 Ring 待結算佇列；不得在回合外啟用能力、造成傷害或寫入存檔。

### 7.6 動畫 config

至少分組管理：

- 受擊閃白時間與強度，以及 `effects/hit` 圖帶結構、`weaponHitEffect.displayScale` 與 `weaponHitEffect.animationDurationMs`。
- `permanentUpgradeConfig.hoverAutoAttack.hitEffectOffset`／`hitEffectTintColor`：自動攻擊相對最新游標位置的左下偏移與 CSS tint，初始為 `(-28, 22)`／`#67d9ff`。
- `equipmentConfig.ring.additionalHitEffectOffset`／`additionalHitEffectTintColor`：Ring 相對觸發批次之手動點擊位置的右上偏移與 CSS tint，初始為 `(28, -22)`／`#ff825c`。
- 每個目標接受武器傷害的最短間隔 `combatConfig.minimumWeaponDamageIntervalPerTargetMs`；此值影響實際輸出，歸屬戰鬥 config 而非動畫 config。
- 抖動時間、距離、頻率與最大旋轉。
- 裂紋的輕微階段血量比例初始為 `0.7`，明顯階段血量比例初始為 `0.35`；必須符合 `0 < 明顯門檻 < 輕微門檻 < 1`。
- 裂紋線寬、透明度、顏色、分支程度與明顯階段錯位上限；錯位上限初始為 `2 px`。
- 噴獎數量、速度、角度、重力與持續時間。
- 金幣圖帶結構、幀率、顯示尺寸、收益到視覺數量的映射與同時存在上限。
- 金幣局部落地範圍、反彈次數、反彈係數、停留時間、收集弧線與錯開時間。
- 本局收益數字滾輪的持續時間、額外輪轉及連續更新節奏。
- 破碎切片、速度、旋轉、重力與淡出。
- 續戰補場內層視覺的起始倍率、放大時間、峰值倍率與回正時間；不得以這些參數控制外層 hit area、戰鬥資格或結算時點。
- Jackpot 傾斜、碰撞回饋、僵直抖動與向下逃跑速度。
- 外掛卡 `33 × 41` 顯示尺寸、箱種容量、右上偏移、卡組固定旋轉、扇形間距／展開角度、繪製順序、逐張點擊範圍、噴出、淡出與 `160 ms` 共通前搖。
- 共用外掛卡稀有度 `N`／`R`／`SR`／`SSR`／`UR`；`N` 不建立光暈，其他稀有度的卡框圓角、清晰描邊、模糊光層、padding、透明度、呼吸與 CSS `#RRGGBB` 顏色均依 rarity config。`UR` 另保存固定斜向漸層的起訖與五個 color stop，不依卡名另設欄位。
- 裝備拋射角度／速度、重力、落地範圍、反彈次數／保留率、停留、比金幣晚抵達的錯開、收集、無金幣 fallback，以及 Ring 追加 hit 偏移與 CSS tint 顏色。
- 結算裝備分組列的 `100 ms` 初始揭示間隔、`400 ms` 揭示階段上限與 `300 ms` 總收益滾動時間；全部歸於 `animationConfig.settlementEquipmentSale`，只影響呈現。
- 落雷圖帶結構、`450 ms` 總播放時間、底端 anchor、`88 × 88` 命中範圍與動畫清理。
- 隕石／爆炸共用大於 `0` 的 `meteorite.displayScale`；傷害區另有大於 `0` 的 `meteorite.damageAreaWidthMultiplier`。第一顆等待目標上限、後續落點候選數、最小距離倍率、圖帶結構、旋轉、位移速度、飛行循環、多顆間隔、爆炸時間、底線對齊與由兩個比例推導的 `D × D` 命中範圍都由 config 管理，實際調整值以 [`effectCardConfig.ts`](../src/configs/effectCardConfig.ts) 為準。
- 龍捲風三段圖帶結構、各段動畫時間、`run` 持續時間、建立數量、初始武器傷害倍率、每目標間隔、顯示比例、傷害高度比例、移動速度、轉向間隔／限角與多顆方向擾動都由 config 管理，實際調整值以 [`effectCardConfig.ts`](../src/configs/effectCardConfig.ts) 為準。

動畫實作讀取 config，不得在各 Sprite 或事件處理器散落相同用途的魔法數字。

## 8. 遊戲數值 config

所有會影響遊戲手感、難度、收益或動畫程度的數值，放在 `src/configs` 下具有清楚名稱的 TypeScript config。

至少涵蓋：

- 主武器穩定 id、名稱、傷害、價格、購買前置與初始武器 id。
- 懸停自動攻擊解鎖價格、自動攻擊間隔等級 `0～3` 的毫秒表與逐級價格，以及相對游標位置的 hit 偏移與 CSS tint 顏色。
- 永久裝備槽等級的額外槽數表與逐級價格；目前只開放等級 `1`，未來第 4 槽沿用同一表追加等級 `2`。
- 各寶箱怪最大血量、基礎收益與生成權重。
- 主倒數、生成間隔與寶箱移動速度。
- Jackpot 血量、獎勵放大、追逐時間、速度、反彈與退場。
- 裝備與效果卡機率、可用集合、效果卡去重規則、各箱種外掛卡容量及效果數值。
- 裝備槽數、可見裝備掉落率、隱藏稀有度分布、Sword 加成、Ring 觸發門檻／傷害倍率／固定間隔、hit 偏移與 CSS tint 顏色。
- 落雷初始道數、隕石初始顆數、龍捲風初始數量、各自的初始武器傷害倍率、目標／落點、移動、傷害間隔與範圍規則。
- 場地排列限制。
- 戰鬥與掉落動畫參數。
- 金幣噴灑、反彈、停留、集中收集與本局收益數字滾動參數。
- 裝備自動出售的金幣基價、稀有度倍率，以及平衡模擬中的 `15%～25%` 出售收益占最終總收益目標；價格與驗證目標分屬 settlement config 與 balance simulation config。

規則：

- config 使用完整、可理解的英文名稱，不使用模糊縮寫。
- 衍生值由來源 config 計算，不保存互相可能矛盾的重複數字。
- 等級表的可購買最高級由目前開放內容推導或在同一永久升級 definition 中定義，不得在 UI、service 與存檔 schema 各寫一份上限。
- config 只保存資料，不建立 PixiJS 物件或混入遊戲流程函式。
- Pixi 視覺顏色在 config 使用容易人工調整的 CSS 色碼字串；需要 packed tint 時只在顯示邊界轉換，不在 config 保存 `0x...` 數字，也不在 ticker 熱路徑重複轉換。
- SCSS 的顏色、間距、字級、模糊程度等純視覺數值留在 SCSS。

## 9. 可測試性邊界

- 生成抽選與候選位置演算法應可注入可控亂數來源。
- 低密度／清場有效目標判定、延後確認、最低剩餘時間、Jackpot 追逐排除、補場目標數、補場許可、重新允許與場內填場結果都必須能以固定實體快照、亂數及 `deltaMS` 重複執行，不依賴 Pixi 顯示 child 數量或真實時間。
- 計時、位移、反彈與動畫進度應可用指定 `deltaMS` 重複執行。
- 懸停自動攻擊的目標／最新游標位置保存、同一目標 move 不重設倒數、leave／失效清除，以及成功傷害後由游標快照加 config 偏移產生命中特效指令，都必須能用純座標與指定 `deltaMS` 測試，不把 Pixi pointer event 物件帶入核心狀態。
- 效果卡與裝備共同候選／容量裁切、可見與隱藏裝備掉落、落雷目標選擇、隕石第一顆目標／等待 fallback、後續落點間距／最遠候選與錯開間隔、龍捲風方向／轉向與多次攻擊去重都使用可注入亂數；相同 seed 與場上狀態必須得到相同結果。
- 稀有度光暈設定解析必須是可獨立測試的純資料映射：`N` 不產生光暈設定，`R`／`SR`／`SSR`／`UR` 只依 rarity 讀取正式 config；效果卡與裝備卡不得因內容 id 或卡框素材得到不同結果。
- 裝備目的地原子保留、實例 identity、穩定排序、換裝／替換／卸下／互換、抵達啟用、背包無效狀態、拋射／落地／反彈進度、Sword 疊加、Ring 換裝邊界／觸發游標快照／序列佇列、暫停前後無補算及回合收尾取消規則，都屬於不依賴 Pixi 顯示物件的可測試核心邏輯。
- 主武器的價格／前置／持有驗證、原子購買／裝備，以及由裝備武器 id 與正式 config 解析本局武器基準，都必須是可測試純資料邏輯。永久升級的價格／前置／最高級驗證、原子購買，以及由固定 config 與等級解析自動攻擊狀態／間隔與槽位數，同樣不得由 React、Pixi 與存檔各自重算；永久升級資料不得保留主武器攻擊力等級。
- 出售資格快照、依 id 分組、稀有度價格、乘算後小計、出售總額與最終總收益都必須是可測試核心邏輯；React 不計算單價或總額，測試不得把正式 config 數字另寫一份。
- 落雷命中集合、隕石第一顆目標偏向／無目標等待 fallback、後續落點間距／最遠候選、縮放後的場外起點與飛行進度、由爆炸實際顯示寬度及傷害範圍倍率推導的底部對齊命中集合、龍捲風階段／移動／碰撞／獨立傷害間隔、單次傷害、取消與連鎖佇列屬於可測試核心邏輯，不依賴 Pixi 顯示物件或真實時間。
- 共用水平圖帶工具必須驗證金幣、武器 hit、落雷、隕石、爆炸與龍捲風三張圖帶的正確 frame 版面，錯誤尺寸需提供足以定位素材的訊息。
- XState 測試使用離散事件，不依賴真實時間。
- 測試從正式 config 讀取平衡數值，不在測試另寫一套攻擊力、血量、掉落率、裝備效果或時間。
- 結算、出售、解鎖與存檔先後順序必須有行為測試，尤其覆蓋飛行中成功掉落不漏算、存檔失敗不揭示假入帳結果，以及中途關閉後補播解鎖提示。
