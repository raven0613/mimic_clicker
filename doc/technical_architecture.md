# 前端與遊戲執行架構

本文件定義初版的渲染、UI、狀態管理、遊戲迴圈、生成排列、動畫與 config 邊界。遊戲行為規則以 [spec.md](./spec.md) 為入口；效果卡細節見[效果卡規格](./effect_cards.md)；存檔細節見[存檔系統規格](./save_system.md)。

## 1. 技術選擇

- 專案原始碼使用 TypeScript。
- 樣式使用 SCSS；CSS 視覺數值留在 SCSS 變數或對應元件樣式中。
- PixiJS v8 負責全螢幕 canvas 戰鬥場地。
- React 負責覆蓋在 canvas 上的 HUD、選單、結算、解鎖、升級與存檔 UI。
- XState 負責離散且有先後限制的遊戲流程。
- Zustand 負責 React 與遊戲橋接所需的低頻記憶體資料。
- IndexedDB 由獨立存檔 service 管理，不由 Zustand 直接持久化。

這些工具不得保存彼此職責內的第二份真實資料。

## 2. 畫面分層

由下至上：

1. 全螢幕 PixiJS canvas。
2. React HUD 疊層。
3. React 結算、解鎖、確認或選單疊層。

### 2.1 PixiJS canvas

負責：

- 寶箱怪與 Jackpot。
- 場地移動、牆面反彈與逃跑。
- 點擊判定與武器命中。
- 效果卡附著、點擊、前搖、攻擊與連鎖。
- 受擊、掉落、噴獎、破碎及其他戰鬥動畫。
- 結算期間的動態裝飾背景。

### 2.2 React 與 SCSS

負責：

- 主倒數條。
- Jackpot 追逐倒數條。
- 金錢、裝備欄與其他 HUD。
- 結算、解鎖、升級、匯入／匯出與重置 UI。
- 結算時覆蓋 canvas 的輕微高斯模糊。

HUD 的非互動區域應讓指標事件穿透到 canvas；按鈕、對話框與結算遮罩才攔截事件。進入結算時，除了 UI 遮罩攔截之外，遊戲流程本身也必須拒絕戰鬥輸入。

右上角金錢 HUD 顯示本局累計收益。它使用 React／SCSS 實作逐位數字滾輪，只接收顯示目標，不參與獎勵計算或入帳。

### 2.3 兩種倒數條

- 主倒數條在正式單局開始時啟動。
- Jackpot 偽裝在普通流中時，不顯示 Jackpot 倒數條。
- 玩家打破 Jackpot 外殼、正式進入追逐時，才顯示並啟動 Jackpot 倒數條。
- Jackpot 追逐結束、擊殺或逃脫後，Jackpot 倒數條消失。
- 倒數真實值由遊戲執行層持有；React 只取得足夠流暢的顯示快照，不驅動遊戲時間。

## 3. 狀態所有權

| 層級 | 保存內容 | 不保存內容 |
| --- | --- | --- |
| XState | 載入、待機、遊戲中、Jackpot 追逐、單局收尾、結算、解鎖提示等流程 | 每幀位置、速度與動畫進度 |
| Zustand | 已載入的局外進度、貨幣、升級、UI 所需結果快照 | XState 已持有的流程狀態、IndexedDB 寫入細節 |
| Pixi runtime | 場上實體、效果卡、座標、速度、血量、逐幀計時與動畫 | 永久進度與存檔格式 |
| Save service | IndexedDB 讀寫、版本與匯入／匯出 | React UI 與 Pixi 顯示物件 |

### 3.1 XState 流程責任

至少需要表達下列離散流程：

```text
loadingSave
→ ready
→ playing
   ├─ jackpotDisguised
   ├─ jackpotWaitingToReturn
   ├─ jackpotChasing
   └─ jackpotResolved
→ finishingRound
→ settlement
→ unlockAnnouncement（可選）
→ ready
```

- XState 只接收 `JACKPOT_REVEALED`、`JACKPOT_TIMER_EXPIRED`、`ROUND_TIMER_EXPIRED`、`JACKPOT_EXITED` 等離散事件。
- 不得每幀向 XState 發送位置、速度或一般寶箱血量。
- 不得在 Zustand 再保存一份可與 machine 不一致的 `gamePhase`。

### 3.2 Zustand 責任

適合保存：

- 生涯完成局數。
- 已解鎖寶箱怪。
- 金幣、特殊素材與永久升級。
- 最近一局結果快照。
- React HUD 需要的低頻資料。

Zustand 是記憶體中的應用狀態，不是存檔系統。載入、購買升級、完成結算或確認解鎖後，由明確的協調流程呼叫 save service。

## 4. PixiJS 遊戲迴圈

- 使用 PixiJS `Application` 自己的 ticker 驅動遊戲更新與渲染。
- 位移、倒數與動畫使用 ticker 的 `deltaMS`，不得把 `deltaTime` 當毫秒。
- 高頻更新直接作用於 Pixi runtime 與顯示物件，不經過 React render 或 Zustand action。
- 暫停、頁籤切換與大型幀落後不得造成單幀超大位移；時間邏輯需有明確上限或補償策略。
- 遊戲更新與純視覺更新必須可分開啟停。

### 4.1 正式單局模式

- 啟用寶箱生成、效果卡附著與觸發、戰鬥輸入、血量、掉落、收益與統計。
- 主倒數與必要的 Jackpot 倒數正常運作。

### 4.2 裝飾背景模式

- ticker 與畫面渲染持續。
- 沿用同一生成器，但以裝飾參數生成乾淨寶箱。
- 停止戰鬥、效果卡、收益、掉落、正式計時與 Jackpot 邏輯。
- 裝飾實體不進入下一局，開始新局前統一清除。

### 4.3 實體移除生命週期

- PixiJS 實體一旦在某幀被移出 runtime 集合並呼叫 `destroy()`，該幀後續流程不得再讀寫它的 position、scale、rotation、事件或子物件。
- 逐幀視覺更新必須把 `container.destroyed` 視為正常的終止狀態並立即返回，不能讓已移除實體的 transform 存取例外中斷共用 ticker。
- 退場路徑必須涵蓋普通寶箱、Jackpot 偽裝流出、Jackpot 擊破及 Jackpot 向下逃離；任何一條路徑都不得因單一實體銷毀而停止主倒數或其他場景動畫。
- 修正此類生命週期 bug 時，必須新增「銷毀後同幀視覺更新不丟例外」的核心回歸測試。

## 5. 場地生成與排列

普通寶箱不使用固定或半固定軌道。

### 5.1 候選位置選擇

1. 在場地水平安全範圍內產生多個連續隨機 X 候選值。
2. 以即將生成卡牌的矩形範圍，與生成區附近現有卡牌矩形計算重疊。
3. 排除超過最大允許重疊比例的候選位置。
4. 從剩餘候選中選擇重疊最少者。
5. 若全部不合格，延後一小段時間重試，不強制建立嚴重遮擋的卡牌。

### 5.2 排列原則

- X 座標不得量化成數條固定線。
- 允許少量重疊以保留自然散落感，但需維持主要點擊區可辨識。
- 卡牌尺寸、場地寬度與裝置比例變化時，重疊計算使用實際顯示矩形。
- 普通卡牌維持由上往下的主要動勢，不以左右蛇行製造散落感。
- Jackpot 真身不受普通排列限制，且渲染層級固定高於普通寶箱。

### 5.3 可調 config

- 水平安全邊距。
- 最大允許重疊比例。
- 候選位置數量。
- 找不到位置時的重試間隔。
- 生成間隔與各寶箱怪生成權重。

## 6. Jackpot 追逐運動

### 6.1 追逐

- 兩次碰牆之間維持直線速度，路徑應可預讀。
- 碰牆時依牆面法線反射速度向量，使入射與反射方向合理。
- 只允許小幅且有上限的角度修正，用來避免完全水平、垂直或永久重複路徑。
- 卡牌旋轉只呈現微幅傾斜，不能連續翻滾。
- 旋轉應快速跟隨動勢並自然回正，不拖延追逐操作。

### 6.2 Jackpot 倒數先耗盡

1. 立即停止 Jackpot 受擊。
2. 保留當下世界座標，播放不產生淨位移的短促抖動僵直。
3. 鎖定當下 X 座標，忽略側牆碰撞，向下直線逃離。
4. Jackpot 倒數條消失。
5. 主倒數、普通生成與其他寶箱戰鬥繼續。

### 6.3 主倒數先耗盡

1. 立即停止所有戰鬥輸入、生成、收益與正式計時，並取消尚在效果卡前搖中的待發動攻擊。
2. 若 Jackpot 正在追逐，播放相同的抖動僵直與向下逃跑。
3. Jackpot 離場後移除 Jackpot 倒數條並完成本局。
4. 若 Jackpot 已被擊殺或已逃脫，不等待不存在的 Jackpot 動畫。
5. 進入 React 結算遮罩與 Pixi 裝飾背景模式。

## 7. 動畫系統

動畫原則是「預備短、命中清楚、收尾快」。純視覺動畫不得延後傷害、死亡、獎勵或流程狀態生效。

效果卡噴出前搖是明確的戰鬥時序，不屬於可任意中斷而不影響結果的純視覺動畫。落雷與隕石都必須等前搖完成才發動；主倒數在前搖期間耗盡則取消待發動攻擊。已發射但尚未落地的隕石仍未結算傷害，也必須在主倒數耗盡時取消。

### 7.1 受擊

- 閃白。
- 以原位置為中心的短促卡牌抖動。
- 微幅後仰、橫向偏移或向上彈動。
- 動畫完成後回到正確邏輯座標，不累積視覺偏移。

#### 7.1.1 每目標武器傷害間隔

- 每個可戰鬥 `RuntimeMimicEntity` 保存 `nextWeaponDamageAllowedAtMs`，初始值允許第一擊立即生效。准入判定使用 runtime 的遊戲經過時間，不使用 `Date.now()`、計時器或真實牆鐘時間。
- 手動點擊與未來武器攻擊在進入既有共用傷害入口前，先比較當前遊戲時間與該實體的下一次允許時間；成功造成武器傷害後才依 `combatConfig.minimumWeaponDamageIntervalPerTargetMs` 推進下一次允許時間。
- 間隔內的攻擊必須回傳未套用傷害，不更新血量、裂紋或任何受擊動畫，也不建立手動 hit 特效。剛好到達下一次允許時間時視為有效，且不同實體的時間互不影響。
- 落雷、隕石與其他效果卡直接進入既有共用傷害／死亡／收益／Jackpot 結算，不讀取或更新武器傷害間隔。間隔只是傷害來源准入規則，不得複製另一套傷害結算。
- Jackpot 偽裝外殼與揭露後真身沿用同一個 runtime 實體及 `nextWeaponDamageAllowedAtMs`；揭露時重設 texture、血量、裂紋與移動資料，但不得重設剩餘武器傷害間隔。實體死亡或離場後隨實體一併清除，不建立全域冷卻表。
- 確定性核心測試必須涵蓋第一擊、間隔內拒絕、剛好到達邊界、不同實體互不影響、效果卡繞過限制，以及 Jackpot 揭露後延續剩餘間隔；測試時間由參數注入，不依賴真實時間。
- 戰鬥與批次平衡模擬必須套用相同的每目標武器准入規則，不得繼續把原始點擊預算全部視為有效傷害；本規則或 config 數值改變時更新平衡版本並重跑完整矩陣。

#### 7.1.2 手動點擊特效

- 可受擊實體的 pointer event 必須把實際 canvas／世界點擊座標傳入手動攻擊入口；只有傷害入口確認該次手動攻擊有效後，才在該座標建立 `effects/hit.png` 特效。
- 手動點擊特效是純視覺回饋，不參與傷害、點擊範圍、裂紋或死亡判定；落雷、隕石及其他非手動傷害不建立此特效。
- `effects/hit.png` 是 `1750 × 218` 水平圖帶，切成 5 張 `350 × 218` frame；AnimatedSprite 使用中心 anchor，顯示寬高分別為 frame 寬高乘上大於 `0` 的 `manualHitEffect.displayScale`，非循環播放時間讀取 `manualHitEffect.animationDurationMs`。切幀尺寸不得隨顯示比例改動。
- 點擊特效建立在獨立的世界特效層，不掛在 Mimic Container 下，因此致死攻擊移除 Mimic 後仍能完成播放；特效 `eventMode` 為 `none`，不得攔截後續點擊。
- 點擊特效的圖帶結構、顯示尺寸與總播放時間由 config 管理。點擊座標及逐幀狀態只存在 Pixi runtime，不進入 XState、Zustand 或存檔。

#### 7.1.3 階段式裂紋

- 裂紋由 Pixi runtime 持有，只是顯示狀態，不進入 XState、Zustand、存檔或戰鬥結算資料。
- 可受擊實體必須同時保留目前血量與目前外觀的最大血量，以純函式依血量比例判定 `intact`、`subtle`、`severe` 三種顯示階段。
- 卡牌顯示順序固定為 Mimic 底圖、裂紋層、受擊閃白層、外掛卡扇形層；裂紋與外掛卡都跟隨 Mimic 父層的座標、縮放、抖動及 Jackpot 微幅旋轉。效果卡與後續裝備卡共用外掛卡扇形層，不各自建立重疊的排列容器。
- 裂紋使用 PixiJS v8 `Graphics`／`GraphicsContext` 建立程序式線條，不新增每種 Mimic 專用裂紋圖片。
- 準備三組固定裂紋圖樣；同一圖樣的輕微與明顯階段共用主裂紋路徑，明顯階段只延伸分支與邊緣效果，不重新抽取裂紋位置。
- 穩定的裂紋幾何應共用 `GraphicsContext`，實體只切換對應階段的 context 或可見狀態，不可在 ticker 中反覆 `clear()` 並重畫。銷毀個別實體時不得連帶銷毀其他卡牌共用的 context。
- 裂紋階段只在生成、受擊後血量改變及外觀身分切換時更新，不進入每幀血量判定。
- 明顯裂縫使用主裂縫兩側的明暗邊緣及最多 `2 px` 的局部視覺錯位營造深度；卡牌本體仍是一個完整實體，不在死亡前拆成多個可自由移動的部分。
- Jackpot 偽裝外殼被擊破時，先切換真身 texture、最大血量與目前血量，再把裂紋階段重置為 `intact`。後續受擊依 Jackpot 真身最大血量重新判定。
- 裝飾寶箱沒有戰鬥血量，不建立或不顯示裂紋層。
- 致死攻擊仍立即建立既有死亡破碎效果、移除場上實體並結算獎勵；裂紋顯示不得插入等待狀態。

### 7.2 噴獎

- 寶箱頭頂不顯示 `+收益` 文字，也不以無具體形狀的圓形粒子代替金幣。
- 每次擊破建立一批有上限的金幣 Sprite；視覺金幣數量依收益強度映射，不影響實際獎勵計算。
- 普通寶箱與 Jackpot 共用同一套金幣生命週期，Jackpot 只提高視覺數量與強度，不建立另一套更新流程。
- 金幣使用 `airborne`、`resting`、`collecting`、`completed` 等明確階段表達拋射、反彈、停留與收集，不套用只能單段移動後淡出的通用粒子模型。
- `airborne` 階段以 `deltaMS` 更新速度與重力，碰到每顆金幣自己的局部落地高度時修正穿透、反射垂直速度，並在完成隨機 2～3 次反彈後進入 `resting`。
- `resting` 階段固定顯示翻轉圖的最後一幀；短暫停留完成後切換 idle texture。
- `collecting` 階段以有明確終點的短促弧線飛向 React 金錢 HUD 提供的 canvas 目標座標，並在結束後回收或銷毀顯示物件。

#### 7.2.1 水平精靈圖帶共用讀取器

- 專案只保留一套水平精靈圖帶切幀工具；金幣、點擊、落雷、隕石與爆炸素材都必須沿用，不得再建立效果專用切幀流程。
- 共用工具接收素材識別、來源寬高、單幀寬高與幀數，驗證後由左至右建立 frame texture。
- `coin/gold_coin_flip` 是 `721 × 103` 的水平圖帶，切成 7 張 `103 × 103` frame texture。
- `effects/thunder` 是 `792 × 256` 的水平圖帶，切成 9 張 `88 × 256` frame texture。
- `effects/hit` 是 `1750 × 218` 的水平圖帶，切成 5 張 `350 × 218` frame texture。
- `effects/meteorite` 是 `1410 × 500` 的水平圖帶，切成 6 張 `235 × 500` frame texture。
- `effects/explode` 是 `1536 × 240` 的水平圖帶，切成 6 張 `256 × 240` frame texture。
- 讀取器只載入一次各素材的原始 texture source，同類顯示物件共享切出的 frame texture，不為每個顯示實體重複載入或複製圖片。
- 讀取器必須驗證來源尺寸、幀尺寸、幀數及總寬是否一致；不符合預期時拋出包含素材路徑、預期尺寸及實際尺寸的錯誤。
- `coin/gold_coin_idle` 是獨立的 `103 × 103` texture，在收集階段開始時切換使用。
- 清除個別 Sprite 或 AnimatedSprite 時不得連帶銷毀其他物件共享的 frame texture 或 texture source。

#### 7.2.2 Pixi 與 React HUD 橋接

- React 金錢 HUD 在掛載及尺寸／位置改變時，將收集目標的 viewport 座標提供給 Pixi runtime；runtime 依 canvas host 的實際矩形換算成本地座標。
- 金幣逐幀座標、幀索引、反彈次數與動畫階段只存在 Pixi runtime，不進入 XState 或 Zustand。
- 邏輯 `roundGold` 在擊殺成立時立即增加；另以明確命名的顯示用本局收益保存數字滾輪目前可追逐的目標，兩者不得互相取代。
- 同一批金幣第一次抵達 HUD 時只發送一次低頻顯示事件，將該批 reward 加入顯示目標；不得逐幀或每顆金幣更新 Zustand。
- 多批金幣抵達順序不同時，顯示目標仍只能累加前進；React 數字滾輪在新目標到達時平滑重定向，最後必須停在正確整數。
- 數字滾輪卸載、動畫中斷或回合收尾都不影響 `RoundResult` 與存檔收益。

### 7.3 死亡破碎

- 優先將現有 Mimic texture 切成多個區塊。
- 各區塊可獨立飛散、旋轉、受重力影響並快速淡出。
- 切片行列、初速、散射、重力、旋轉與淡出時間由 config 管理。
- 破碎效果可被場景清理或流程切換中斷，不保留失效物件。

### 7.4 效果卡、落雷與隕石

#### 7.4.1 效果卡組裝與附著

- 卡框 `effects/card_frame/normal`、落雷 icon `effects/card_icon/thunder` 與隕石 icon `effects/card_icon/meteorite` 都是 `264 × 328`；每張卡使用一個卡框 Sprite 與對應 icon Sprite，以相同 anchor、位置及顯示尺寸疊在效果卡 Container 內。
- 卡框與 icon 初始共同顯示為 `33 × 41`；右上偏移依縮放後的卡片尺寸重新配置，使突出比例維持一致，點擊矩形也使用縮放後尺寸。
- Runtime Mimic 持有單一外掛卡集合，不再以單一 `effectCard | null` 表達；效果卡與未來裝備卡都由同一個右上角扇形 Container 排列，但各卡仍保留類別、內容 id、卡框素材 id、稀有度與各自結算狀態。
- 同一 Mimic 的效果卡 id 必須唯一；落雷與隕石都不得重複生成來填滿較高卡片容量。
- 普通寶箱與 Jackpot 偽裝外殼讓每種效果卡各自進行一次可注入的候選機率抽選。候選數超過容量時，使用公平的無重複隨機裁切，不以 definitions 陣列順序固定偏向其中一種卡。
- Jackpot 真身沿用同一個純資料選卡模組，但使用保證選取策略：不執行普通候選機率，先以 `attachedCardConfig.capacity.jackpot.countSelectionChances` 決定 `minimum` 或 `maximum` 目標，再從當下可用內容池公平無重複抽選。兩個機率必須形成完整分布；不得另建一套平行的 Jackpot 卡片資料或排列系統。
- 可用唯一卡數少於目標時回傳全部可用卡；因此目前只有落雷與隕石時真身必定取得兩張。內容池大於目標時才需要裁切，且相同 seed 與內容池必須產生相同結果。
- 純資料排列函式依卡片總數與索引產生固定座標、角度及繪製順序。單張使用固定位置；多張形成撲克扇形，卡組整體微幅順時針旋轉，不讀取亂數。
- 外掛卡扇形位於 Mimic 右上角並跟隨 Mimic 移動與受擊動勢；卡片中心間距必須讓每張 icon 保留可辨識區域，後方卡先繪製、前方卡後繪製。
- 卡框與 icon 使用 nearest-neighbor 取樣並盡量對齊整數座標；不得套用 Blur 或 Glow filter。
- 扇形 Container 內先放所有光暈，再放所有卡面，避免任何卡片的光暈覆蓋其他 icon；光暈與卡面可使用分離的子層，但必須由同一份排列結果同步 transform。
- 每張卡依正式稀有度取得小範圍放射漸層光暈。`normal` 使用淡藍光暈，`SSR` 使用更亮的橘黃色光暈；兩者目前都明確指定 `normal` 卡框素材。相同稀有度共用穩定的 Graphics 資源，ticker 只更新 alpha 呼吸，不更新位置／縮放，也不反覆清除及重畫幾何。
- Mimic 本體維持既有點擊矩形；外掛卡突出部分逐張以自身旋轉矩形判定，所有矩形與 Mimic 本體形成聯集並導向同一攻擊事件，不建立涵蓋大片空白的外接點擊區，重疊區也只送出一次攻擊。
- 初始容量為 `normal = 1`、`rare1 = 1`、`rare2 = 2`；Jackpot 偽裝沿用外皮容量。Jackpot 真身目標張數與選取權重讀取 `attachedCardConfig.capacity.jackpot`，可用種類不足時全部插上，不得用重複效果卡補滿。

#### 7.4.2 前搖與重新掛層

- 攜帶者死亡或 Jackpot 偽裝外殼被打破時，先取得尚未結算的全部外掛卡；效果卡必須在 Mimic 被銷毀或換皮前逐張重新掛到世界特效層，保留扇形中的當下世界 transform。
- 同一寶箱的所有效果卡在同一事件中一起開始各自的前搖，不依卡片排列順序串行。效果卡在世界特效層以 config 驅動噴出、旋轉與淡出；共通初始前搖總時間為 `160 ms`。
- 每張效果卡前搖完成後移除自己的顯示物件，再依 effect id 分派至落雷或隕石流程。共通前搖系統不得持有落雷／隕石專用命名或結算分支以外的攻擊狀態。
- 效果卡與裝備卡共存時，效果前搖與裝備死亡掉落流程可以並行。裝備卡仍依鬆動程度進行最終掉落判定，不因和效果卡共用扇形而保證取得。
- Jackpot 偽裝外殼被打破時可以不建立金幣獎勵，但外殼上的效果卡與裝備卡仍必須完整結算；換成真身前不得因 Container 銷毀而遺失插卡狀態。
- 偽裝外殼的外掛卡完成上述結算後不得轉移到真身；揭露流程依 Jackpot 自己的 config 與當下內容池建立新的外掛卡集合。擊破真身時，該集合再依一般效果觸發與裝備死亡掉落入口結算，並可與 Jackpot 金幣噴獎並行。
- 主倒數在前搖期間耗盡時清除待發動卡片，不呼叫效果傷害或連鎖；已發射但尚未落地的隕石也一併清除。
- 場景清理必須同時清除附著中、噴出中與已發動的效果卡顯示物件，不得存取已銷毀 Container。

#### 7.4.3 落雷攻擊與動畫

- 落雷發動時以可注入亂數從當下有效實體選擇目標，位置取發動瞬間座標，不持續追蹤。
- 落雷 AnimatedSprite 使用底部中央 anchor，目標座標代表底端命中點，`88 × 256` 雷柱從該點向上顯示。
- 傷害判定使用以底端命中點為中心的 `88 × 88` 純資料正方形，不以整條 Sprite bounds 或透明像素作為戰鬥真相；邊長由 frame 寬度推導。
- 手動攻擊與落雷必須共用同一個傷害、死亡、收益與 Jackpot 結算入口；傷害來源只用來區分武器間隔與觸發規則，不複製結算流程。落雷不讀取或更新武器傷害間隔。
- 每道落雷建立前先決定該次命中實體集合，每個實體只處理一次，避免九幀動畫重複扣血。
- 落雷動畫使用 9 張共用 frame texture 的非循環 AnimatedSprite，初始總時間為 `450 ms`；各幀時間由總時間與幀數推導。
- 傷害在 AnimatedSprite 開始播放時立即生效，播放完成後只移除顯示物件，不再改變戰鬥結果。
- 落雷或隕石造成的效果卡擊破以待發動佇列建立下一段 `160 ms` 前搖，不在目前傷害迭代或同步呼叫堆疊中遞迴觸發。

#### 7.4.4 隕石攻擊與動畫

- 隕石流程在發射前先以可注入亂數決定落點。令 `V = explosionFrameWidth × meteorite.displayScale`、`D = V × meteorite.damageAreaWidthMultiplier`；落點限制必須確保底部對齊的 `D × D` 傷害正方形完整位於目前 canvas 內。
- 軌跡計算使用純資料函式：隕石順時針旋轉 `45°` 後，以 local 正 Y 對應的世界方向作為右上到左下飛行向量；再使用乘上 `meteorite.displayScale` 後的 frame 寬高計算旋轉 bounds，沿反向射線求出整個顯示範圍位於畫面外的起點。
- 起點、落點、單位方向、剩餘距離與發射時間是戰鬥時序資料；ticker 以 `deltaMS` 和 `meteorite.flightSpeedPixelsPerSecond` 更新距離，最後一步必須 clamp 到落點，不得穿越後再回拉。
- 隕石使用 6 張 `235 × 500` frame、底部中央 anchor 與 `meteorite.animationCycleDurationMs` 控制的循環動畫；實際顯示寬高為 frame 寬高乘上 `meteorite.displayScale`。移動與 frame 循環讀取同一 ticker，但顯示比例、位移速度與動畫速度三者互不取代。
- 每卡建立的隕石數量讀取 `meteorite.initialMeteoriteCount`。第一顆立即發射，後續每顆累加可注入亂數依 `meteorite.minimumLaunchIntervalMs` 與 `meteorite.maximumLaunchIntervalMs` 產生的間隔；每顆獨立決定落點，飛行距離可以不同。
- 抵達時先取得當下仍有效的實體集合，以與爆炸底部共同對齊的 `D × D` 正方形計算命中，再透過既有共用傷害入口逐一結算四倍初始武器傷害。`D` 必須由爆炸實際顯示寬度乘上 `damageAreaWidthMultiplier` 推導；每顆對同一實體最多一次，不依爆炸幀重複結算。
- 抵達同一刻銷毀隕石 Sprite 並建立 6 張 `256 × 240` frame、底部中央 anchor、由 `meteorite.explosionAnimationDurationMs` 控制的非循環爆炸動畫；顯示寬高同樣乘上 `meteorite.displayScale`。隕石飛行前端、爆炸底部與傷害區底線使用完全相同的落點座標，不因縮放新增 position offset。
- 主倒數耗盡時，尚未發射或仍在飛行的隕石不得落地或造成傷害；已完成傷害的爆炸可以由場景清理統一中斷，不影響既有結果。
- `EffectCardSystem` 只擁有共通前搖與類型分派；落雷和隕石各自的活動狀態放在對應模組。手動攻擊、落雷與隕石必須共用同一個傷害／死亡／收益／Jackpot 結算入口，不複製戰鬥結算。

### 7.5 動畫 config

至少分組管理：

- 受擊閃白時間與強度，以及 `effects/hit` 圖帶結構、`manualHitEffect.displayScale` 與 `manualHitEffect.animationDurationMs`。
- 每個目標接受武器傷害的最短間隔 `combatConfig.minimumWeaponDamageIntervalPerTargetMs`；此值影響實際輸出，歸屬戰鬥 config 而非動畫 config。
- 抖動時間、距離、頻率與最大旋轉。
- 裂紋的輕微階段血量比例初始為 `0.7`，明顯階段血量比例初始為 `0.35`；必須符合 `0 < 明顯門檻 < 輕微門檻 < 1`。
- 裂紋線寬、透明度、顏色、分支程度與明顯階段錯位上限；錯位上限初始為 `2 px`。
- 噴獎數量、速度、角度、重力與持續時間。
- 金幣圖帶結構、幀率、顯示尺寸、收益到視覺數量的映射與同時存在上限。
- 金幣局部落地範圍、反彈次數、反彈係數、停留時間、收集弧線與錯開時間。
- 本局收益數字滾輪的持續時間、額外輪轉及連續更新節奏。
- 破碎切片、速度、旋轉、重力與淡出。
- Jackpot 傾斜、碰撞回饋、僵直抖動與向下逃跑速度。
- 外掛卡 `33 × 41` 顯示尺寸、箱種容量、右上偏移、卡組固定旋轉、扇形間距／展開角度、繪製順序、逐張點擊範圍、噴出、淡出與 `160 ms` 共通前搖。
- 已存在卡框稀有度的小範圍放射光暈顏色、漸層節點、外擴距離、基礎透明度、呼吸幅度與週期。
- 落雷圖帶結構、`450 ms` 總播放時間、底端 anchor、`88 × 88` 命中範圍與動畫清理。
- 隕石／爆炸共用大於 `0` 的 `meteorite.displayScale`；傷害區另有預設 `1` 且大於 `0` 的 `meteorite.damageAreaWidthMultiplier`。圖帶結構、旋轉、位移速度、飛行循環、多顆間隔、爆炸時間、底線對齊與由兩個比例推導的 `D × D` 命中範圍都由 config 管理，實際調整值以 [`effectCardConfig.ts`](../src/configs/effectCardConfig.ts) 為準。

動畫實作讀取 config，不得在各 Sprite 或事件處理器散落相同用途的魔法數字。

## 8. 遊戲數值 config

所有會影響遊戲手感、難度、收益或動畫程度的數值，放在 `src/configs` 下具有清楚名稱的 TypeScript config。

至少涵蓋：

- 玩家初始主武器攻擊力。
- 各寶箱怪最大血量、基礎收益與生成權重。
- 主倒數、生成間隔與寶箱移動速度。
- Jackpot 血量、獎勵放大、追逐時間、速度、反彈與退場。
- 裝備與效果卡機率、可用集合、效果卡去重規則、各箱種外掛卡容量及效果數值。
- 落雷初始道數、隕石初始顆數、各自的初始武器傷害倍率、目標／落點與範圍規則。
- 場地排列限制。
- 戰鬥與掉落動畫參數。
- 金幣噴灑、反彈、停留、集中收集與本局收益數字滾動參數。

規則：

- config 使用完整、可理解的英文名稱，不使用模糊縮寫。
- 衍生值由來源 config 計算，不保存互相可能矛盾的重複數字。
- config 只保存資料，不建立 PixiJS 物件或混入遊戲流程函式。
- SCSS 的顏色、間距、字級、模糊程度等純視覺數值留在 SCSS。

## 9. 可測試性邊界

- 生成抽選與候選位置演算法應可注入可控亂數來源。
- 計時、位移、反彈與動畫進度應可用指定 `deltaMS` 重複執行。
- 效果卡候選抽選／容量裁切、落雷目標選擇、隕石落點／錯開間隔與多次攻擊去重都使用可注入亂數；相同 seed 與場上狀態必須得到相同結果。
- 落雷命中集合、縮放後的隕石場外起點與飛行進度、由爆炸實際顯示寬度及傷害範圍倍率推導的底部對齊命中集合、單次傷害、前搖／飛行取消與連鎖佇列屬於可測試核心邏輯，不依賴 Pixi 顯示物件或真實時間。
- 共用水平圖帶工具必須驗證金幣、點擊、落雷、隕石與爆炸的正確 frame 版面，錯誤尺寸需提供足以定位素材的訊息。
- XState 測試使用離散事件，不依賴真實時間。
- 測試從正式 config 讀取平衡數值，不在測試另寫一套攻擊力、血量或時間。
- 結算、解鎖與存檔先後順序必須有行為測試，尤其覆蓋中途關閉後補播解鎖提示。
